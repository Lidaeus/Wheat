## 5. 当前结果为什么有研究价值

### 5.1 平台本身是重要发现

当前平台现象非常重要，因为它说明至少存在以下几种可能：

1. 统一复评器当前对不同协议的区分度不足
2. `train-only` 口径下，最终参数盆地在当前数据上高度集中
3. 当前 `Final_Score` 过于聚合，掩盖了协议差异
4. 某些优化器或序列虽然内部运行轨迹不同，但最后都回到同一组预测
5. 主矩阵维度中至少有一部分已经不是当前问题的主要控制因子

无论哪一种成立，这都不是失败，而是研究推进到下一层问题的信号。

### 5.2 运行代价已经拉开，但精度没有拉开

虽然当前结果同分，但算力代价并不相同。

例如：

- Maize 上 O1 组合常见 `run_model_invocations ≈ 178`、`dssat_treatment_calls ≈ 534`
- Maize 上 O2 + S2 组合可到 `run_model_invocations ≈ 1348`、`dssat_treatment_calls ≈ 4044`
- Wheat 上 O2 + S2 也显著高于 O1

这意味着：

- 当前 Phase 1 已经形成了**非常重要的成本-收益事实**
- 即：**更高的算力消耗并没有在当前统一复评分数上换来收益**

这是 Phase 2 设计的核心依据之一。

## 6. 对论文写作的直接启示

### 6.1 第一阶段结果部分不应写成“冠军表”

当前最稳妥的写法不是：

- “某组合最终胜出”

而应写成：

- 第一阶段在统一正式口径下完成了五作物全量筛选
- 但结果呈现显著平台现象
- 主矩阵维度在当前训练集聚合评分下未形成可分离主效应
- 不同协议在计算成本上差异巨大，但在统一复评精度上未拉开差距

### 6.2 第一阶段更适合写成“问题识别阶段”

论文中可以把 Phase 1 定位为：

- 主矩阵已完成
- 但最重要发现不是排序，而是平台
- 平台提示：
  - 需要更强的机制分析
  - 需要更有辨识力的二阶段设计
  - 需要把“最低分比较”升级为“成本-收益 + 结构差异 + 机制归因”

### 6.3 第一阶段结果部分建议突出三条主叙事

1. **工程层**
   - 五作物正式全量矩阵已稳定跑通
   - 统一输出链路、后处理链路、算力统计链路已建立

2. **结果层**
   - 全矩阵出现高强度平台
   - 主分数与 aggregate metrics 在统一复评下均未拉开

3. **方法层**
   - 当前主问题已经从“谁赢”转向“为什么区分不开”
   - 因而 Phase 2 需要聚焦机制辨析，而不是继续做同层穷举

## 7. 对 Phase 2 设计的直接启示

### 7.1 Phase 2 不应继续扩大同层矩阵

当前不建议的方向：

- 再补更多 `W × O × S × G`
- 再加更多 repetition 试图直接打破平台
- 直接把 `W1 / W7 / S3 / O4 / O5` 混入同层 Phase 1 扩展表

原因很明确：

- 当前问题不是“矩阵没跑够”
- 而是“当前统一复评下，矩阵维度没有显示出分辨率”

### 7.2 Phase 2 应聚焦四类问题

#### P2-A：目标一致性与统一复评辨识度

目标：

- 判断平台是由统一复评器过强聚合导致，还是由真实预测完全一致导致

建议：

- 对代表性组合做 treatment-level 与 metric-level 差异分析
- 对比内部优化目标与统一 `Final_Score`
- 增加更细粒度结构指标，而不仅是 mean NRMSE

#### P2-B：边界、参数与贴边机制

目标：

- 判断平台是否来自边界吸附或参数冻结

建议：

- 做边界敏感性实验
- 对关键作物统计 parameter shift / boundary hit
- 对 O1/O2 的最终参数进行簇分析，而不只看总分

#### P2-C：成本-收益分析

目标：

- 判断 O2、S2、复杂协议在当前问题上是否值得其额外成本

建议：

- 把 `dssat_treatment_calls`、`run_model_invocations`、`dssat_wall_sec` 提升为 Phase 2 主表字段
- 形成“无收益但高成本”的识别规则

#### P2-D：结构性增强，而不是平面扩张

目标：

- 尝试用更能打破平台的设计增强区分度

优先方向：

- 替代 split 或更强验证设计
- 指标消融
- 代表性组合的重复复验
- `MGDA -> O1`

## 8. 我建议的下一步执行动作

### 8.1 立即执行的下一步

当前最合理的“接着第一阶段继续做”的动作不是补跑同层矩阵，而是：

1. **冻结这次 Phase 1 正式全量结果为当前阶段正式版本**
2. **做结果分析与图表准备**
3. **启动 Phase 2 的机制辨析批次**

### 8.2 建议的 Phase 2 启动顺序

1. **P2-1：代表性组合 treatment-level 差异复核**
   - 目标是确认是否真的是“预测完全相同”
2. **P2-2：O1/O2 统一复评一致性分析**
   - 目标是确认平台是否由统一评分器造成
3. **P2-3：成本-收益汇总表**
   - 目标是形成论文中很强的一张对照表
4. **P2-4：`MGDA -> O1` 定向复验**
   - 作为最有希望真正打破平台的增强层方向

## 9. 当前阶段最稳妥的判断

### 9.1 已经能说的

- 第一阶段正式全量运行已完成
- 正式五作物矩阵可稳定执行
- 当前结果呈现显著平台
- 不同协议的运行成本差异巨大
- 现阶段最需要的是机制分析，而不是继续平铺矩阵

### 9.2 还不能说的

- 不能说 `G3` 已显著优于 `G1`
- 不能说 `S2` 已显著优于 `S1`
- 不能说 O1 与 O2 已形成稳定排序
- 不能说某个 `W` 已成为 Phase 1 推荐冠军
- 不能说当前 train-only 结果已经支持泛化结论

## 10. 一句话结论

当前 Phase 1 的真正阶段性结论不是“我们已经找到赢家”，而是：**我们已经用当前正式口径证明了五作物主矩阵可完整执行，但结果在统一复评下出现了强平台现象；因此下一步必须从“继续补跑同层组合”切换到“解释为什么平台出现、哪些机制掩盖了协议差异、以及 Phase 2 如何用更有辨识力的设计打破平台”。**
