## 一句话结论

- W8 在 sandbox 中被判为 `negative_optimization` 的主因不是算法失效，而是 **baseline 比较口径不公平**
- O2 `pestpp-ies` 之前并未真正接入 sandbox 运行链，本轮已完成接入并实跑成功
- 修正比较口径后，W8 结果恢复合理；接入 O2 后结果进一步提升

## 本轮做了什么

- 对齐 W8 权重实现：将 sandbox 侧改为与 DSSAT-PEST 一致的“按观测组最大值取权重”
- 排查并修正 baseline 口径：新增“可行域 baseline”，避免用边界外官方参数压边界内优化结果
- 接入 O2 `pestpp-ies` 真实执行链：包含阶段参数激活、PEST 构建、IES 执行、最优结果回收

- 调整 matrix 判定规则：`negative_optimization` 改为对照“可行域 baseline”

## 关键判断

### 判断 1：W8 的“负优化”主要是比较基线问题

- 原 baseline 直接使用 DSSAT 官方参数：`[9.33, 3.12, 331.4, 12.87, 62.22, 2.215, 86.00]`
- 但 sandbox 当前边界要求：
  - `P5 >= 550`
  - `G2 <= 60`
  - `G3 <= 2.1`
  - `PHINT >= 95`
- 也就是说，baseline 运行在 **边界外**，而优化器只能在 **边界内** 搜索
- 这种比较会系统性放大 `negative_optimization`

### 判断 2：sandbox 与 PEST 侧的 W8 实现原本并非完全一致

- `eval.py` 原逻辑：同组指标拼接后取整体最大值
- `build_pest_setup.py` 逻辑：按观测组分别取组内最大值
- 已统一为后者，消除实现口径偏差

### 判断 3：O2 失败不是 DSSAT 崩溃，而是观测集被过滤为空

- 初次接入 O2 时，报错：`No usable observations`
- 根因：阶段运行时只传了 `PEST_ACTIVE_METRICS`，未同步传 `DSSAT_EXTRA_SUMMARY_VARS`
- 结果：A 文件中的 `ADAP / MDAP / CWAM / HWUM` 未进入观测集合，阶段过滤后观测为 0
- 修复后 O2 顺利跑通

## 关键证据

| 项目 | 结果 |
|---|---:|
| 外部 baseline（官方参数，未裁剪） | 0.417561 |
| 可行域 baseline（裁剪到 sandbox 边界） | 0.469857 |
| W8 + O1 + S2 + G3 | 0.463468 |
| W8 + O2 + S2 + G3 | 0.370379 |

## 证据解读

- 若对照外部 baseline，W8 + O1 会被误判为负优化：`0.463468 > 0.417561`
- 若对照可行域 baseline，W8 + O1 实际已经改善：`0.463468 < 0.469857`
- W8 + O2 进一步改善到 `0.370379`，优于两类 baseline
