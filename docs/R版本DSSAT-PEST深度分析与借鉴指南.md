# DSSAT-PEST (R版本) 与 mvp_pest_mgda (Python版本) 深度对比与借鉴分析

本文档记录了对 `c:\DSSAT48\Wheat\DSSAT-PEST\DSSAT_PEST.r` 源代码的深度评估，以及在多目标参数率定项目中我们应如何吸收其经验并进行架构升级。

## 1. 避免局部最优：SIEVE better CSPs vs 现代全局优化

### R 版本的做法 (SIEVE better CSPs)
R 版本中的 `SIEVE better CSPs` 步骤本质上是一种**“多起点启发式策略”（Multi-start approach）**。
因为 PEST 默认使用的是基于梯度的 Levenberg-Marquardt (GLM) 算法，这是一种纯粹的“局部搜索”算法，极易陷入局部最优解。R 版本通过生成一批随机参数（例如10组），全部运行一遍模型，然后挑出拟合度最高的1组作为 PEST 的起始点，以此来尽量规避陷入劣质局部最优的问题。

### 我们的升级方案 (Python/SciPy生态)
我们不需要手写“随机生成-运行-排序”的粗糙循环，现代 Python 生态提供了更强大的全局寻优算法：
*   **PEST++ IES (迭代集合平滑器)**：在 `mvp_pest_mgda` 生产环境中，若需全局寻优，可直接将引擎从 `pestpp-glm` 切换为 `pestpp-ies`。IES 会在参数空间中撒下一张大网（如同时维护 50 个参数集合的 Ensemble），这些点通过伪梯度相互通信并整体向全局最优解滑落。这不仅避免了局部最优，还能提供参数的不确定性分析（置信区间）。
*   **沙盒评估 (eval.py)**：在 Autoresearch 的评估沙盒中，我们将引入 `scipy.optimize.dual_annealing`（模拟退火）或 `differential_evolution`（差分进化）等自带跳出局部极小值能力的全局优化器，以替代容易卡死的纯梯度下降法。

## 2. 多作物适配的架构设计

### R 版本的做法
R 版本通过硬编码的方式对多种作物进行了适配：
*   它为玉米（`MZCER046.pmt`）、水稻（`RICER046.pmt`）、大豆（`SBGRO046.pmt`）等作物分别准备了 PEST 模板文件。
*   在 `ParameterOutput.csv` 表格中，集中存储了所有作物的参数上下界（如 Maize 的 P1/P2，Wheat 的 P1V/P1D，Soybean 的 CSDL 等）。

### 我们的借鉴与升级
*   **吸纳科学经验**：R 版本的 `ParameterOutput.csv` 是一笔宝贵的农业科学财富。里面的参数范围（Min/Max）和关键生理指标可直接作为我们项目的默认先验知识。
*   **数据驱动的动态架构**：R 版本每换一种作物，都需要手动维护基于字符串截取的死板模板（`.pmt` / `.tpl`），极易因 DSSAT 版本升级而崩溃。我们的 Python 方案 `dssat_io.py` 利用 `pyemu` 实现了完全的**“数据驱动”**。要支持新作物，只需新建对应的 JSON 配置文件（如 `project_maize.json`），填入相应的参数 bounds 即可，系统会自动解析并生成合规的 PEST 模板。

## 3. 核心揭秘：R 版本的观测指标分组与权重分配机制

通过解析 `DSSAT_PEST.r` 第 189-192 行及 `ParameterOutput.csv` 结构，其权重分配逻辑非常巧妙，本质上是 **“基于变异系数(CV)的自适应尺度归一化 + 用户自定义权重的指数惩罚”**。

其数学运作机制分为三步：

1.  **基础概率函数 (高斯似然)**
    *   `OUT_fitness1 <- exp(-(Sim - Obs)^2 / 2 / ((CV * Obs)^2))`
    *   该公式计算了一个介于 $[0, 1]$ 之间的适应度 (Fitness)，即正态分布概率密度函数的核心部分。
    *   它假设观测误差的标准差并不是固定的，而是与观测值大小成正比：$\sigma = CV \times Obs$（CV 默认设为 0.5）。
    *   **动态平衡效果**：这一步精妙地将不同量纲的指标（如数千级别的产量和个位数级别的 LAI）进行了归一化，使其相对误差具有可比性。

2.  **分配用户自定义权重 (指数放大法)**
    *   `OUT_fitness11 <- OUT_fitness1 ^ Out_user`
    *   `Out_user` 来自表格中用户定义的权重（例如开花期权重 100，产量权重 1）。
    *   在数学上，$e^{-E}$ 的 $W$ 次方等于 $e^{-W \times E}$。这意味着**用户权重直接作为乘数作用在了相对平方误差上**。权重越大的指标，其指数项衰减得越剧烈，从而迫使优化器优先满足该指标。

3.  **合并总指标 (连乘)**
    *   `OUT_fitness2 <- prod(OUT_fitness11)`
    *   最终的总适应度是所有指标的加权适应度的连乘。在对数空间中，连乘等价于将所有加权误差求和（即典型的加权最小二乘法 WLS）。

**结论**：
R 版本的这种 “CV-based 归一化 + 指数惩罚” 机制在物理意义和数值稳定性上都具有极高的参考价值，它将被纳入我们 Autoresearch 候选的 `strategy.py` 权重方案库中进行对比评测。

## 4. 核心架构：为何在沙盒中使用 SciPy (Nelder-Mead/退火) 而非直接调用 PEST？

在项目的 Autoresearch 沙盒（`eval.py`）中，我们没有直接调用官方的 `pestpp-glm.exe`，而是使用 Python 自带的 SciPy 优化器，核心原因在于 **“控制权”** 与 **“AI 自动编程的适配性”**：

1. **损失函数 (Loss Function) 的控制权（最致命）**：
   真实的 PEST 是一个 C++ 编译程序，其目标函数（加权残差平方和）被硬编码在底层。虽然可以调权重，但**无法改变数学公式本身**。我们引入 AI 的目的是探索前沿的权重计算公式（如基于对数转换、CV方差倒数等）。只有使用 SciPy 的优化器，AI 写的 `strategy.py` 才能真正接管“什么是好，什么是坏”的评判标准。
2. **运行速度与反馈周期**：
   PEST 每次运行需要通过 `pyemu` 构建庞大的 `.pst`、`.tpl`、`.ins` 文件。对于 AI 每几分钟就需要验证一次新代码的敏捷迭代来说，这种文件 I/O 过于沉重。SciPy 优化器直接在内存中传递数组，将单次评测时间压缩在可接受范围内。
3. **为 MGDA（多梯度下降算法）铺路**：
   MGDA 需要在外部计算不同指标的梯度以寻找帕累托最优下降方向。SciPy 提供了一个可拆解的白盒寻优框架，为后续多目标算法的接入提供了基础。

**架构蓝图（降维打击与升维部署）**：沙盒里的 SciPy 是“试验田”，验证 AI 发明的数学公式；真实的 PEST 是“重武器”，等试验田选出最佳公式后，再将其反向翻译注入 PEST 控制文件，进行生产级别的并行率定。

## 5. Autoresearch 落地策略：两阶段“仿真到现实 (Sim-to-Real)”架构

考虑到大语言模型 (LLM) 的 API 超时限制和昂贵的等待成本，我们设计了**两阶段解耦验证法**：

*   **阶段一：AI 极速生成与沙盒验证 (AI 参与，秒级反馈)**
    准备一个极速版的数学替代模型（如简单的二次函数模拟 DSSAT），让 AI 快速生成多种权重策略的代码（`strategy.py`），并立即验证数组操作和逻辑无误。
*   **阶段二：官方 DSSAT 无人值守真机评测 (脱离 AI，批处理运行)**
    关闭 AI 调用，使用本地批处理脚本加载 AI 跑通的所有策略，调用搭载了真实 DSSAT 引擎和全局退火优化器的重量级 `eval.py`，在夜间自动跑完真实农业数据的评测并输出基准报告。

## 6. 指标分组与率定顺序 (借鉴与重构)

通过对 DSSAT-PEST 中 `ParameterOutput.csv` 的梳理，我们发现指标在物理意义上有着强烈的内在逻辑。我们不应该将所有指标揉成一团丢进优化器，而应该参考 AgMIP 和标准 DSSAT 率定规范，进行分组和顺次率定。

### 6.1 指标分组逻辑 (Metric Grouping)
将观测指标（Outputs）按物理功能分为三大类，以避免量纲差异造成的“大数吃小数”现象：
1.  **物候期 (Phenology)**: 开花期 `ADAP`、成熟期 `MDAP` (单位: 天)。这是作物生长的基础时间轴。
2.  **生长与冠层 (Growth & Canopy)**: 最大叶面积指数 `LAIX`、成熟期地上部总生物量 `CWAM` (单位: 指数 / kg/ha)。这代表了作物光合作用的能量积累过程。
3.  **最终产量 (Yield)**: 籽粒产量 `HWAM`、单粒重 `HWUM` (单位: kg/ha / g)。这是最终的产出结果。

### 6.2 顺序率定策略 (Sequential Calibration: 先物候、后生长、最后产量)
若同时优化所有 7 个品种参数（如小麦的 P1V, P1D, P5, G1, G2, G3, PHINT），容易引发高维空间中的“异物同效（Equifinality）”问题——即错误的参数组合偶尔也能碰出正确的最终产量，但中间过程完全是错的。

借鉴物理建模的思想，我们设计了**分步降维率定管道**：
*   **Phase 1 (物候期)**: 冻结 G1, G2, G3。仅使用 `ADAP` 和 `MDAP` 的误差，优化发育参数 `P1V`, `P1D`, `P5`, `PHINT`。确保生命周期卡准。
*   **Phase 2 (生长/冠层)**: 冻结发育参数。仅使用 `LAIX` 和 `CWAM` 的误差，优化光合与叶片扩展参数 `G1` (或者特定的冠层系数)。确保生物量积累正确。
*   **Phase 3 (产量分配)**: 冻结物候与生长参数。仅使用 `HWAM` 的误差，优化生殖生长阶段的分配参数 `G2`, `G3`。确保收获指数 (HI) 和最终产量达标。
*   **Phase 4 (微调兜底)**: 以 Phase 1-3 的结果为起点，在极小的 bounds 内，引入 Autoresearch 筛选出的“最优多目标权重公式”，进行全参数的全局微调。

### 6.3 尚未考虑的潜在挑战 (Checklist)
1.  **多处理间的一致性 (Treatment Sensitivity)**：一个好的权重方案必须惩罚“在充分灌溉下极准，但在干旱胁迫下极差”的现象。我们需要在 Loss 计算中引入“跨处理方差惩罚”。
2.  **缺失值掩码 (Masking Missing Data)**：像 LAI 等指标往往在某些试验处理中并未观测（例如 DSSAT 输出的 `-99.0`）。我们的 `strategy.py` 必须能够自动识别并掩蔽 (Mask) 这些无效观测，否则会导致 Loss 爆炸。
3.  **作物特异性指数 (Crop-Specific Exponents)**：如同 R 版本中给产量和 LAI 赋予了不同的指数惩罚（Yield ^ 10，LAI ^ 1），不同作物对指标的敏感度不同。我们需要在未来的配置文件中预留 `importance_exponent` 字段。

### 7.2 主观干预机制 (importance_exponent) 的工程意义

我们在配置文件中显式保留了 `importance_exponent` 字段。它直接服务于“将农业领域知识注入机器学习循环”的核心目标：
1. **打破纯数学优化的盲目性**：AI 在纯粹的均方根误差 (RMSE) 空间中寻找最小值时，可能牺牲了农学家极其看重的“籽粒产量”，而去极度拟合一条并不重要的 LAI 曲线。
2. **非线性惩罚屏障**：当 Yield 的指数被设为 10（而 LAI 设为 1）时，模型如果对产量拟合较差，其 Loss 惩罚将以指数级爆炸。这等同于在数学空间中为“产量”建起了一道巨大的悬崖，迫使优化器优先保证产量正确，而后再去修饰冠层生长的细节。这种机制完美复刻了 R 版本中 `OUT_fitness11 <- OUT_fitness1 ^ Out_user` 的精髓。
