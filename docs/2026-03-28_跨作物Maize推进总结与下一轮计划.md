## 4. 对这些结果如何归纳与分析

### 4.1 当前可以确认的研究结论

1. **跨作物框架有效。**  
   当前代码已经不仅能服务 Wheat，也能在 Maize 上完成从配置解析、参数写回到 DSSAT/PEST 调用的全链路运行。

2. **O2 在当前 Maize 样例上优于 O1。**  
   无论是 quick 还是 standard 预算，O2 的 `Final_Score` 都低于 O1，说明其在当前样例上有更好的总体拟合表现。

3. **统一矩阵显示存在显著的 engine × crop interaction 信号。**  
   在 Wheat 中，O1 持续优于 O2；在 Maize 中，O2 持续优于 O1。现阶段这更适合解释为“优化引擎表现具有问题依赖性”，其中作物类型、参数结构、观测结构和实现细节都可能共同参与。

4. **当前 quick 与 standard 的差异都很小。**  
   这说明当前预算档位至少在 Wheat/Maize 这两个样例上都还没有把结论方向翻转，O1/O2 的相对排序目前是稳定的。

5. **当前研究阶段不设计验证集，因此现阶段比较的是“统一配置下的拟合表现”，而不是泛化能力。**  
   这不是一个遗漏，而是本研究当前阶段的明确边界。论文表述中必须忠实记录这一点。

### 4.2 结果中的细节信号

从标准预算结果看：

- O2 在 `HWUM` 上表现较好，`TRAIN_HWUM_NRMSE = 0.056248`
- O2 的 `ADAP`、`MDAP` 也保持较低误差
- 但 O2 在 `LAIX` 与 `CWAM` 上仍然存在一定偏差，尤其 `LAIX` 的 `TRAIN_LAIX_NRMSE = 0.391510`

这说明当前 O2 的改进更像是“在总体目标下取得了更优折中”，但并不表示所有单项指标都已达到理想水平。对于论文写作，这一点很重要，因为它说明：

- 我们的优化结果不是简单单调全面变好
- 不同目标之间仍存在权衡
- 这恰好支持后续继续推进多目标优化与分阶段校准研究

对 Wheat/Maize 统一矩阵进一步观察，还能得到两个更重要的信号：

1. **Wheat 中 O1 的优势是多指标同时占优，不像是偶然由单一指标拉出来的。**
2. **Maize 中 O2 的优势更像是由少数关键指标驱动出来的总分优势，尤其在 `HWUM` 上更突出。**

因此，当前更合理的判断不是“某个引擎天然更适合某个作物”，而是：

> 不同作物对应的率定问题结构不同，而不同优化引擎在这些问题结构上的表现也不同。

### 4.3 现阶段最可能的原因与工作假设

当前出现 “Wheat：O1 明显优于 O2；Maize：O2 稳定优于 O1” 的结果，至少可能来自以下五类原因：

1. **真实的问题结构差异。**  
   Wheat 与 Maize 的参数维度、参数语义和阶段式率定可分解性不同。Wheat 当前 7 个参数中物候控制更强，least-squares 可能更容易在阶段式率定中快速收敛；Maize 当前 6 个参数与观测结构组合下，IES 可能更容易找到更好的总体折中解。

2. **目标函数实现并非完全同构。**  
   O1 直接在 `eval.py` 内部按当前权重和分组计算残差；O2 则通过 `build_pest_setup.py` 构造 PEST 观测权重，再依据 `phi` 选出最优 realization。虽然外部配置统一，但内部优化准则并不是严格同一个数学对象，这可能放大不同引擎的行为差异。

3. **关键指标主导效应。**  
   Maize 中 O2 的优势并不是所有单项指标同时提升，而更像是由少数关键指标显著改善后带动总分下降。因此 O2 在 Maize 上的“优势”暂时更像某类目标结构下的优势，而不一定是全面优势。

4. **边界吸附与参数补偿。**  
   当前最优参数中已有多处边界贴附现象，这通常意味着边界设置、目标冲突或参数可辨识性在共同作用。若某个引擎更容易把解推到边界，它在不同作物上的表现可能会被边界结构放大。

5. **样本规模与偶然性。**  
   当前 Wheat 仅 6 个处理，Maize 仅 3 个处理，而且尚未扩展到五作物。此时出现的跨作物差异信号值得重视，但还不足以直接上升为“普遍规律”。

基于以上分析，现阶段最稳妥的论文表达应是：

> 当前结果提示优化引擎表现可能具有明显的问题依赖性，并且这种依赖性在不同作物样例上呈现出不同方向；但在扩展到更多作物前，不宜将其直接表述为普遍性的作物依赖定律。

### 4.4 当前结论的边界

本轮结果虽然有效，但仍属于**阶段性结果**，原因有四点：

1. 当前 Maize 只基于单个样例 `UFGA8201`
2. 当前 Wheat/Maize 总共只覆盖两个作物
3. 当前处理数仍然有限
4. 当前研究**明确不设计验证集**，因此所有结论都应被解释为“统一配置下的拟合比较”，而不是泛化能力比较

因此，现阶段最稳妥的表达应是：

> 我们已经证明跨作物自动率定框架可在 Wheat 与 Maize 上稳定运行，并形成了统一 O1/O2 对照矩阵；但要将当前观察到的引擎差异上升为论文中的普遍性结论，还需要扩展到更多作物，并通过重复运行、边界对照和目标一致性对照来检验其稳定性。

- **Wheat / Soybean / Rice 更偏向 O1。**

- **Maize / Cotton 更偏向 O2。**  
  `pestpp-ies` 在这两类作物上更容易给出更优的总分折中，说明 ensemble-based 搜索在这些问题上可能更能适应目标冲突、边界吸附或多峰结构。

- **预算增加的收益并不均匀。**  
  有些作物从 quick 到 standard 的提升很小，甚至几乎不变，这意味着当前比较的决定因素更可能是“搜索机制差异”，而不是单纯预算不够。

- **引擎内部损失值不能跨引擎直接比较。**  
  例如 Cotton 中 O1 的 `loss_value` 极大，但 `Final_Score` 仅略差于 O2；这说明 O1 内部残差和 O2 的 PEST `phi` 并非同一标度，跨引擎公平比较应继续以统一 `Final_Score` 为主，而不能直接拿内部优化损失横比。

### 10.3 当前最稳妥的研究表述

基于五作物矩阵，现阶段最稳妥的论文式表达应是：

> 在统一评分口径、统一预算档位、统一分阶段率定设置下，O1 与 O2 在不同作物上的相对表现并不一致。五作物结果表明，优化引擎的优劣具有明显的问题依赖性，其差异不宜被简化为某一引擎的普适优势。

## 11. 机制猜想

当前五作物结果并不支持“作物种类本身直接决定最优引擎”这种过强说法，但支持以下更具体、也更可检验的猜想。

### 11.1 猜想 A：决定排序的不是作物名称，而是率定问题结构

更合理的解释是：

- 参数维度
- 参数间补偿关系
- 指标冲突程度
- 阶段式可分解性
- 边界形状与初值位置

这些因素共同定义了一个“率定问题结构”，而 O1/O2 对不同结构的适应性不同。

对应到当前五作物，可做如下初步推测：

- Wheat、Soybean、Rice 的当前问题结构更适合 O1 的连续局部调整
- Maize、Cotton 的当前问题结构更适合 O2 的 ensemble 搜索与整体折中

### 11.2 猜想 B：目标实现路径差异放大了引擎表现差异

当前 O1 与 O2 虽然共享同一外部实验配置，但内部优化对象并不完全相同：

- O1 直接在 [eval.py](file:///c:/DSSAT48/Wheat/autoresearch_sandbox/eval.py) 中按当前权重与阶段逻辑计算残差
- O2 通过 [build_pest_setup.py](file:///c:/DSSAT48/Wheat/mvp_pest_mgda/src/build_pest_setup.py) 构建 PEST 观测与权重，再由 `pestpp-ies` 以 `phi` 驱动更新

因此，当前观察到的“引擎差异”中，可能同时混有两部分：

1. 真正来自优化算法本身的差异  
2. 来自目标表达路径不完全同构的差异

这也是为什么后续必须做“目标一致性对照实验”。

### 11.3 猜想 C：边界吸附与固定参数比例会显著影响 O1/O2 排序

Cotton 的修复过程已经暴露出一个重要结构信号：

- 同一配置中存在多组固定边界参数
- O1 在未过滤固定参数前会直接失败
- 过滤后虽可稳定运行，但最终仍落后于 O2

这提示我们：

- 固定参数比例高
- 可调参数跨度不均衡
- 最优解贴边界

这三类现象可能会显著改变不同优化器的有效搜索空间，从而改变排序。

### 11.4 猜想 D：少数关键指标可能主导最终排序

当前 Maize 与 Cotton 中，O2 的优势更像是由少数关键指标推动出来的总分优势，而不是所有指标同步改善。

这意味着：

- 若弱化某个关键指标的权重，排序可能翻转
- 若移除某个关键指标，O1/O2 的差距可能显著缩小
- 当前“引擎优劣”部分上是在比较“谁更能服务当前权重体系”

因此，后续必须做指标消融与权重扰动实验。

### 11.5 猜想 E：当前预算档位不是主导因素

五作物矩阵中，quick 与 standard 并没有改变引擎胜负方向，因此一个很自然的推论是：

> 当前差异更可能来自搜索机制与目标结构匹配，而不是因为某个引擎“还没给够预算”。

这条猜想的好处是它可直接检验：只需要继续上调预算或加重复，就能判断排序是否会翻转。

## 12. 后续验证实验设计

以下实验全部遵循当前研究边界：

- 不设计验证集
- 统一使用全处理评分
- 继续沿用五作物统一矩阵的数据口径

### 12.1 实验一：重复运行稳定性

目的：判断当前排序是否稳定，尤其检验 O2 的随机性影响。

设计：

- 对每个作物的 O2 至少做多 seed 重复运行
- O1 作为确定性基线，仅保留少量重复用于排查外部运行噪声
- 每次记录 `Final_Score`、各指标 NRMSE、最终参数、边界命中情况

输出：

- 各作物 O2 的均值、标准差、最优值、最差值
- O1/O2 排序翻转次数
- 代表参数的离散程度

判据：

- 若 O2 方差很小且排序不翻转，则当前作物依赖性信号可信度提高
- 若 O2 方差很大，则当前结论应降级为“趋势性观察”

### 12.2 实验二：目标一致性对照

目的：分离“算法差异”和“目标表达差异”。

设计：

- 收集每个作物上 O1 与 O2 的代表参数解
- 用统一 [eval.py](file:///c:/DSSAT48/Wheat/autoresearch_sandbox/eval.py) 评分逻辑对两类解重新复评
- 若可行，再把 O1 解与 O2 解都映射到 PEST 口径下做二次评价

输出：

- `Final_Score` 排名
- O2 内部 `phi` 排名
- 两种排名是否一致

判据：

- 若同一组参数在统一复评分数下仍保留原排序，则更像算法差异
- 若排序显著变化，则说明当前差异有较大一部分来自目标实现路径不完全一致

### 12.3 实验三：边界敏感性实验

目的：判断当前结论是否被边界结构放大。

设计：

- 对五个作物统一设置 3 套 boundary layer：当前边界、适度放宽、适度收紧
- 分别运行 O1 与 O2
- 记录最优参数是否贴边、贴边比例、总分变化幅度

输出：

- 边界命中率
- 各引擎 `Final_Score` 变化
- 排序是否翻转

判据：

- 若放宽边界后排序翻转，说明原结果受边界吸附强烈影响
- 若排序基本不变，说明作物依赖性更可能来自问题结构本身

### 12.4 实验四：指标消融与权重扰动

目的：判断是否存在单一关键指标主导。

设计：

- 对五作物分别进行以下对照：
  - 去掉 `HWUM`
  - 去掉 `LAIX`
  - 去掉 `CWAM`
  - 对关键指标权重做减半与加倍
- 重新运行 O1/O2

输出：

- 排序变化情况
- 每个作物对关键指标的敏感度
- “优势是否仍存在”的稳定性统计

判据：

- 若去掉单一指标后排序立即翻转，则当前引擎优势是“指标主导型”
- 若多数消融下排序仍稳定，则当前优势更接近整体问题结构差异

### 12.5 实验五：阶段式率定结构消融

目的：判断当前结论是否依赖 `s2_sequential_phase`。

设计：

- 在五作物上对比：
  - `s1_naive_joint`
  - `s2_sequential_phase`
- 保持其他口径一致

输出：

- 两种阶段结构下的 O1/O2 排序
- 各阶段主导指标的变化

判据：

- 若排序只在 `s2` 下成立，说明当前结论部分依赖阶段式可分解结构
- 若 `s1` 和 `s2` 结论一致，则说明引擎差异更稳健

### 12.6 实验优先级建议

最优执行顺序建议为：

1. 重复运行稳定性
2. 目标一致性对照
3. 边界敏感性实验
4. 指标消融与权重扰动
5. 阶段式率定结构消融

这个顺序的逻辑是：先判断现象是否稳定，再判断差异是否公平，最后再解释机制。

- **显式随机初始化稳定性实验**：回答“当 O2 启用随机初始群体后，其结果波动有多大”

如果这条趋势继续保持，那么结论就会进一步加固：**Maize 当前更适合把 O2 当作诊断框架，而不是主率定框架。**

### 17.2 近期分析

这些结果放在一起后，已经能支撑几个比较稳的分析判断：

1. **Maize 当前真正有价值的问题，不再是“哪次 O2 恰好分数更低”，而是“为什么不同框架在同一问题上会呈现完全不同的收敛机制”。**

2. **MGDA 已经不仅仅是“偶然更优”，而是在机制上更适合当前问题。**  
   它不是只给出一个更低的单点分数，而是保留了更丰富的 Pareto archive，这意味着它更适合支撑后续的折中分析、目标组拆解和论文化表达。

3. **O2/IES 暴露出的主问题是阈值效应，而不是单纯算力不够。**  
   目前看到的不是“预算越大越慢但越好”，而更像是：  
   - 小 ensemble：更稳，但搜索塌缩；  
   - 中/大 ensemble：可探索性上来，但 prior-data conflict 快速主导；  
   - 因此 IES 的主矛盾是 ensemble 分布与观测约束之间的不匹配。

4. **NSGA-II 当前不是主力，但保留了方法学对照价值。**  
   它证明“基于群体的多目标进化”这条路是通的，只是现配置下种群规模和代数仍偏保守，导致前沿展开不充分。

### 17.3 当前结论

这一轮可以正式沉淀下来的近期结论是：

- **结论 1：Maize quick O2 的历史口径混乱问题已经修正，相关主表可视为已完成清洗。**
- **结论 2：Maize standard O2 不是当前主攻方向，因为它的首要问题是稳定完成一次默认复现。**
- **结论 3：在 phase3_formal 档位下，MGDA 已成为当前最有效、最值得继续投入的率定框架。**
- **结论 4：O2 当前最有研究价值的角色是“诊断 prior-data conflict 与阈值行为”，而不是担任主率定器。**

### 17.4 研究判断

如果把研究目标从“刷一个最低分数”提升到“建立可靠且可解释的率定框架”，那么当前最合理的判断应当是：

- **主线从 O2 转向 MGDA。**  
  MGDA 现在最符合“有效率定框架”的标准：结果更强、前沿更丰富、后续更容易做折中分析。

- **O2 转成辅助诊断线。**  
  O2 不应再被当作默认主工作流，而应被用来回答两个明确问题：  
  `prior-data conflict 是由哪些观测组主导？`  
  `ensemble 尺度在哪些阈值附近从可用跳到失稳？`

- **NSGA-II 保留为方法对照线。**  
  它适合用来检验“MGDA 的优势来自框架本身，还是只是某次超参命中”。

换句话说，**下一阶段的目标不是“再把所有精力压在 IES 上”，而是构建一个以 MGDA 为中心、以 O2 为诊断、以 NSGA-II 为对照的框架研究体系。**

### 17.5 下一轮研究重点

下一轮建议聚焦四个重点，每个重点都直接服务于“靠拢有效率定框架”：

1. **重点 A：把 MGDA 变成可复验的主流程。**  
   不只看一次最好分数，而是看不同 seed / start-mode 下是否稳定产出高质量 Pareto 前沿。

2. **重点 B：从 Pareto archive 中提取“有解释力的代表解”。**  
   不再只报一个最优点，而是明确 `高 HWAM`、`低 LAIX/CWAM 偏差`、`综合折中最优` 这几类代表方案。

3. **重点 C：把 O2 的 threshold map 做扎实。**  
   目标不是优化 O2，而是把 `ies_num_reals / subset_size / noptmax` 与 `run failure / conflict / final_score` 的关系描清楚。

4. **重点 D：尝试混合框架。**  
   核心思路是 `MGDA 找 Pareto 前沿 -> 选代表解 -> 用 O1 做局部收敛或精修`，检验“多目标探索 + 单目标收敛”是否能兼得稳定性与精度。

### 17.6 下一轮实施方案

下一轮不建议再做大而散的试验，而建议按工作包推进：

**工作包 1：MGDA 主流程复验**

- 固定 `phase3_formal + O5` 为主配置。
- 以 `default / lhs / random` 三类起点各跑一组，比较分数、archive 大小与代表解形态。
- 每组都落盘保存 Pareto archive、代表参数、关键指标误差拆解。
- 目标不是刷新最低分，而是证明 MGDA 在不同初始化下是否仍保持明显优势。

**工作包 2：Pareto 代表解筛选**

- 从 MGDA archive 中抽取 3 类代表点：  
  `产量优先`、`冠层/生物量优先`、`综合折中`。
- 分别对这些点做指标拆解，重点看 `HWAM / LAIX / CWAM / ADAP / MDAP / HWUM` 的偏差结构。
- 形成“参数组合 -> 误差结构 -> 农艺解释”的映射。

**工作包 3：O2 阈值诊断**

- 只保留少量但有信息量的格点，例如：  
  `32/8/2`、`40/12/2`、`48/16/3`、`56/20/3`、`72/24/4`。
- 全部不设超时，避免人为截断行为机制。
- 每个格点统一记录：  
  `initial failures`、`conflict count`、`是否进入 upgrade ensembles`、`最终分数/是否长时间停滞`。
- 目标是绘出 O2 的“稳定性-探索性”阈值图，而不是继续把它当最优器。

**工作包 4：混合框架验证**

- 从 MGDA 代表解中选择 2–3 个点，作为 O1 或局部最小二乘的初值。
- 检查混合流程是否能在不丢失多目标结构的前提下进一步压低综合误差。
- 如果有效，这条线将比单独追 O2 更接近“工程上可用的率定框架”。

### 17.7 实施优先级

下一轮的优先顺序建议固定为：

1. **先做 MGDA 复验与 archive 解读；**
2. **再做 O2 阈值诊断；**
3. **最后做 MGDA -> O1 的混合框架验证。**

这样安排的原因很直接：

- MGDA 已经展现出最高的当前价值；
- O2 现在更适合解释问题，而不是承担主结果；
- 混合框架只有在主流程与诊断线都清楚后，才有意义去验证。

如果按上述方案推进，下一轮最应该争取的产出不是单一最优分数，而是这三类成果：

- **一条可复验的 MGDA 主率定流程；**
