## 2. 极端参数是怎么选的

本轮“极端参数”不是作为“真实最优品种”的候选，而是作为一次 **链路打通测试** 使用，目的只有一个：确认“改写 CUL 参数后，DSSAT 输出会不会真的变”。

链路测试中使用的两组参数是：

- 官方参数 / 初始参数：`[9.33, 3.12, 331.4, 12.87, 62.22, 2.215, 86.0]`
- 极端参数：`[60.0, 95.0, 999.0, 45.0, 65.0, 2.5, 167.0]`

对应顺序均为：

- `P1V`
- `P1D`
- `P5`
- `G1`
- `G2`
- `G3`
- `PHINT`

选取规则不是“来自文献推荐最优值”，而是下面四条工程规则：

1. **必须明显远离官方参数**
   - 这样才能让模型响应足够大，便于检查参数是否真的传导到 DSSAT。
2. **尽量取当前 sandbox 边界的外沿**
   - 例如 `P1D=95`、`P5=999`、`G2=65`、`PHINT=167` 都是现边界的上沿。
3. **必须能安全写回固定宽度 CUL**
   - 例如 DSSAT 的 `.CUL` 是固定宽度格式，数值必须在列宽内可表示。
4. **它是诊断向量，不是生理推荐向量**
   - 它的角色类似“压力测试输入”，不是论文里要声称“该小麦品种应取这些值”。

因此，极端参数的定位应该理解为：

- **用于证明参数敏感性存在**
- **用于验证运行链路和目标函数链路**
- **不直接作为生理结论**

## 4. 为什么要改这些范围

核心原因不是“为了让优化器更容易赢”，而是 **旧边界与当前官方 cultivar 本身发生了冲突**。

官方 cultivar 参数在 [project_wheat.json:L99-L106](file:///c:/DSSAT48/Wheat/autoresearch_sandbox/project_wheat.json#L99-L106) 中是：

- `P1V = 9.33`
- `P1D = 3.12`
- `P5 = 331.4`
- `G1 = 12.87`
- `G2 = 62.22`
- `G3 = 2.215`
- `PHINT = 86.0`

而旧的 DSSAT-PEST / 先前 sandbox 边界要求：

- `P5 >= 550`
- `G2 <= 60`
- `G3 <= 2.1`
- `PHINT >= 95`

这意味着：

- 官方参数本身有 **4 个维度落在旧边界之外**
- baseline 可以用官方值跑到 `0.295629`
- 优化器却只能在另一块被裁剪过的可行域里搜索

这会导致两个问题：

1. **不公平比较**
   - baseline 和优化器不在同一可行域里。
2. **边界贴附与平台现象**
   - 当多个关键参数被迫卡在边界上时，Pareto archive 很容易看起来“变化不大”或“都贴边”，从而形成表面上的平台。

所以这次调整的实质是：

- **把官方 cultivar 拉回可搜索空间**
- **消除“baseline 在边界外、优化器在边界内”的结构性不公平**
- **给 phase3 多目标诊断留出足够响应空间**

## 5. 这些变化是否符合植物生理常识

结论不能简单回答“完全符合”或“完全不符合”，更准确的说法是：

- **其中一部分是“与当前案例官方品种一致”的合理放宽**
- **另一部分是“为诊断保留的工程外沿”，应谨慎作为生理先验使用**

### 5.1 可以认为相对合理的部分

- `P5` 从 `550` 放宽到 `300`
  - 因为当前官方品种就是 `331.4`。
  - 换句话说，若继续坚持 `P5 >= 550`，等于直接宣告“官方 cultivar 本身不合法”。
- `PHINT` 从 `95` 放宽到 `80`
  - 因为当前官方品种是 `86.0`。
  - 这同样说明旧下界与当前案例品种不一致。
- `G2` 从 `60` 放宽到 `65`、`G3` 从 `2.1` 放宽到 `2.5`
  - 这两项是对官方值 `62.22`、`2.215` 的小幅包络扩展，不是数量级上的放飞。

### 5.2 需要更谨慎看待的部分

- `P1V` 从 `60` 到 `65`
- `G1` 从 `30` 到 `45`

这两项更像是：

- 为了避免搜索一开始就被硬边界截断
- 为了给 phase3 archive 暴露更多灵敏度
- 为了验证“参数变化是否能推着输出变化”

但它们目前更适合归类为：

- **诊断性边界**
- **工程性缓冲边界**

而不是直接归类为：

- **已经被本地实测资料充分支持的最终生理先验**

## 6. 当前更稳妥的解释口径

为了避免后续论文或报告出现归因混乱，当前建议把边界正式分成三层，而不是两层。

### 6.1 官方合法域

角色：

- 作为 **绝对合法性外框**
- 用来判断某组参数是否仍在 DSSAT 官方作物文件可接受范围内
- 作为所有后续修订边界不能任意突破的上位约束

当前配置来源见 [project_wheat.json:L88-L126](file:///c:/DSSAT48/Wheat/autoresearch_sandbox/project_wheat.json#L88-L126)：

- `P1D 0–200`
- `P5 100–999`
- `G1 10–50`
- `G2 10–80`
- `G3 0.5–8.0`
- `PHINT 30–150`

### 6.2 DSSAT-PEST 继承边界

角色：

- 作为 **历史继承口径**
- 用于和 DSSAT-PEST 结果做严格可比对照
- 用于附录或方法学消融，回答“如果沿用旧搜索窗，结果会怎样”

当前配置来源见 [project_wheat.json:L127-L165](file:///c:/DSSAT48/Wheat/autoresearch_sandbox/project_wheat.json#L127-L165)：

- `P1V 5–60`
- `P1D 0–95`
- `P5 550–999`
- `G1 5–30`
- `G2 30–60`
- `G3 0.5–2.1`
- `PHINT 95–167`

### 6.3 当前项目修订边界

角色：

- 作为 **当前主实验口径**
- 用于正式 phase3 主结果
- 兼顾官方 cultivar 合法性、项目诊断需求与优化可搜索性

当前配置来源见 [project_wheat.json:L166-L204](file:///c:/DSSAT48/Wheat/autoresearch_sandbox/project_wheat.json#L166-L204)：

- `P1V 5–65`
- `P1D 0–95`
- `P5 300–999`
- `G1 5–45`
- `G2 30–65`
- `G3 0.5–2.5`
- `PHINT 80–167`

### 6.4 三层边界的分工原则

- **官方合法域** 负责回答“参数是否合法”
- **DSSAT-PEST 继承边界** 负责回答“与历史 DSSAT-PEST 搜索窗相比会怎样”
- **当前项目修订边界** 负责回答“在不排除官方 cultivar 邻域的前提下，项目当前最合理的主实验设置是什么”

因此，后续文稿里不应再把这三层混写成同一个“参数范围”概念，而应明确区分：

- 合法性外框
- 历史继承对照
- 当前主实验口径

## 7. 本轮验证说明了什么

本轮验证已经证明：

- 极端参数会显著改变 DSSAT 输出
- 参数改变会传导到 phase3 目标值
- 先前的 `0.295629` 平台并不只是“优化器无能”，还包含了 **边界设定与参数生效路径** 的问题

因此，当前最关键的阶段性结论是：

- **我们已经从“参数改了但模型不变”进入到“参数可驱动模型变化”的阶段**
