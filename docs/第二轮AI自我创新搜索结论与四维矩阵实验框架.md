# 第二轮 AI 自我创新搜索结论与四维矩阵实验框架

## 1. 背景

本轮工作的目标不是继续手工构造单个权重公式，而是在边界受控的前提下，让 AI 在 `strategy.py` 内自主生成候选损失函数，并通过真实 DSSAT 运行结果进行筛选。评价对象仍然是小麦实测处理的产量与 LAI，总体目标是让模拟值整体更接近观测值。

本次总结聚焦两件事：

1. 沉淀上一轮正式创新搜索的结论，便于后续复现。
2. 将后续研究方向从“继续盲搜公式”升级为“四维矩阵”稳定性实验。

## 2. 正式创新搜索设置

### 2.1 搜索边界

- 允许 AI 修改 `strategy.py` 中的损失构造方式
- 不允许改动 DSSAT 驱动、参数边界与观测数据
- 候选公式仅在以下受控维度内变异：
  - 产量误差变换：`nrmse`、`relative_mae`、`smape`、`log_rmse`、`huber_rel`
  - LAI 误差变换：同上
  - 聚合器：`sum`、`l2`、`mean_max`
  - 形状参数：`1.0`、`1.15`、`1.35`
  - 平衡惩罚权重：`0.0`、`0.1`、`0.25`、`0.45`
  - 处理间一致性惩罚：`0.0`、`0.05`、`0.12`、`0.2`
  - 交叉项惩罚：`0.0`、`0.05`、`0.12`

### 2.2 正式搜索轮次

- 搜索时间：`2026-03-25 16:10:49`
- 模式：AI 自我创新
- 轮数：2
- beam width：2
- seed limit：4
- 评价方式：真实 DSSAT 运行后，以 `Final_Score` 作为候选公式优劣标准

## 3. 核心结果

### 3.1 基线与优胜者

- 当前基线策略得分：`0.366630`
- 最优候选：`AI_sma_log_l2_s115_b025_t012_c005`
- 最优得分：`0.302820`

相对于本轮基线，最优候选将最终分数降低了约 `17.4%`，说明“受控创新”并非无效搜索，而是确实找到了更优的权重设计。

### 3.2 最优公式结构

最优公式对应的结构可概括为：

- 产量误差：`SMAPE`
- LAI 误差：`log-RMSE`
- 主聚合器：`L2`
- 形状系数：`1.15`
- 产量/LAI 平衡惩罚：`0.25`
- 处理间差异惩罚：`0.12`
- 交叉项惩罚：`0.05`

其直觉解释是：

- 对产量采用 `SMAPE`，增强对比例误差的敏感性，避免大数值处理主导整体目标。
- 对 LAI 采用 `log-RMSE`，减弱尺度差异带来的不均衡。
- 用 `L2` 聚合而非简单求和，强化“短板指标”效应。
- 再叠加平衡项与处理方差项，抑制“整体均值好看但单个处理偏差很大”的情况。

## 4. 候选公式谱系

### 4.1 谱系主干

本轮最有研究价值的主干不是随机跳跃，而是存在一条清晰的连续改进路径：

1. `Current_Strategy_Baseline` → `0.366630`
2. `AI_log_log_sum_s10_b00_t005_c00` → `0.333153`
3. `AI_nrm_log_l2_s115_b01_t012_c005` → `0.313942`
4. `AI_sma_log_l2_s115_b025_t012_c005` → `0.302820`

这条主干说明：

- 单纯把两类指标都切换到对数域有帮助，但还不够。
- 将产量和 LAI 使用不同误差变换，比“双指标同构”更有效。
- 将聚合器从 `sum` 换成 `l2`，并加上适度平衡惩罚，是本轮最关键的结构跃迁。

### 4.2 失败分支的启发

若干变体虽然形式接近优胜者，但表现明显回落：

- `AI_log_log_l2_s115_b025_t012_c005` → `0.368911`
- `AI_sma_hub_l2_s115_b025_t012_c005` → `0.351051`
- `AI_sma_log_mean_max_s115_b045_t012_c005` → `0.530214`
- `AI_sma_log_l2_s135_b025_t02_c005` → `0.359451`

这些回落提示：

- 产量端改用 `SMAPE` 是有效增益，不只是“任意换一个指标都能变好”。
- `mean_max` 在当前小样本处理中偏于激进，稳定性差于 `l2`。
- 处理间惩罚过强时，容易把搜索推向过度保守区域。
- 形状系数继续加大到 `1.35` 后，可能放大局部误差过度，损害整体最优性。

## 5. 与第一轮创新的关系

第一轮创新搜索的最佳结果为：

- `AI_nrm_nrm_l2_s10_b025_t005_c00`
- 得分：`0.326176`

第二轮正式搜索进一步把最优值推进到 `0.302820`。这说明前一轮找到的“L2 聚合 + 平衡项”方向是正确的，但第二轮继续证明：

- 产量与 LAI 不应机械共享同一种误差变换
- LAI 的对数型处理更有价值
- 适中的处理间一致性惩罚可以进一步改善最终评价

## 6. 当前结论的边界

虽然上一轮搜索是有收获的，但目前还不能把 `AI_sma_log_l2_s115_b025_t012_c005` 直接视为“最终公式”，原因有三：

1. 其优越性仍然是在单一优化流程下观察到的。
2. 不同预算下，随机型优化器可能存在排名波动。
3. 不同率定顺序下，同一权重方案的表现可能改变。

因此，真正值得做的下一步不是继续盲搜，而是研究：

- 同一组候选权重在不同优化器上是否仍然排名靠前
- 同一组候选权重在不同预算下是否保持稳定
- 同一组候选权重在不同率定顺序下是否具有一致解释

## 7. 四维矩阵实验框架

下一阶段实验框架升级为四个正交维度：

### 7.1 维度一：候选权重方案

固定一组候选权重仍然是正确方向，但当前候选集还不够细化。真正需要固定的，不只是“名字列表”，而是一个有来源、有类别、有适配边界的候选库。

当前更合理的起始候选集应至少分为四层：

1. **AI 创新层**
   - `Current_AI_Winner`

2. **统计基线层**
   - `2_Inverse_RMSE`
   - `5_Mean_Normalization_NRMSE`
   - `6_Log_transformation`

3. **DSSAT-PEST / AgMIP 半经验层**
   - `3_CV_based_R_version`
   - `8_AgMIP_Two_step_WLS`

4. **多目标对照层**
   - `9_Pareto_Dominance`
   - `Pure_MGDA_Baseline`

其中必须强调两点：

- `3_CV_based_R_version` 与 `8_AgMIP_Two_step_WLS` 不能再被排除在矩阵之外。它们虽然在上一轮沙箱里表现不佳，但这恰恰说明它们需要在“不同优化器 × 不同率定顺序 × 不同预算”下被重新审视，而不是被过早淘汰。
- 候选权重不应只记录公式本身，还应记录三个附加标签：`来源`、`是否动态调权`、`适配的优化器家族`。否则后续即使分数接近，也很难解释为什么某些方案只在特定算法下有效。

结合 `c:\DSSAT48\Wheat\DSSAT-PEST\PEST_Files\pst_weight.txt` 与 `ParameterOutput.csv` 可以看出，DSSAT-PEST 的半经验方案并不是简单的“主观拍脑袋加权”，而是把输出变量先按生理类型分组，再按组内误差尺度反推权重。典型信号包括：

- 物候类：`ADAP`、`MDAP`
- 冠层/生长类：`LAIX`、`CWAM`
- 产量/收获类：`HWAM`、`HWUM`、`HIAM`

因此，第三轮搜索前，权重候选集应从“几个数学公式”升级为“AI 公式 + 统计公式 + 半经验公式 + 多目标基线”的混合库。

### 7.2 维度二：优化器

当前优化器数量不算太少，但家族覆盖还不够合理。问题不在于“个数偏少”，而在于：

- 局部无导数法占比偏高
- 缺少适合作物遗传参数全局搜索的群体/集合类方法
- 缺少真正的多目标前沿算法用于研究对照

因此，优化器应划分为两个层级：

**第三轮正式矩阵的核心层**

- `pest_glm_grouped`
- `pest_glm_native`
- `anneal_nm`
- `powell`

这一层的目标是回答：在当前算力可承受、且已经接入沙箱的条件下，哪些权重方案跨“梯度型 / 退火型 / 局部直接搜索型”依然稳定。

**后续扩展研究层**

- `PEST++ IES`
- `Differential Evolution / CMA-ES`
- `NSGA-II 或 MNSGA-II`

其科学分工应明确如下：

- `PEST++ IES` 更适合做全局初始化、集合平滑和不确定性刻画
- `Differential Evolution / CMA-ES` 更适合做黑箱全局标定，对复杂非凸目标更稳健
- `NSGA-II / MNSGA-II` 更适合做“权重后移”的真正多目标对照，而不是继续把所有目标强压成单一标量

相反，`nelder_mead` 作为单独一类继续保留的价值已经下降，因为 `anneal_nm` 内部已经包含了退火后接 `Nelder-Mead` 的局部细化。第三轮正式矩阵不必再让它单独占一个主轴位置。

此外，还有两类算法应暂时与主矩阵分开：

- `GLUE / DREAM-zs / MCMC`：它们更适合参数不确定性推断，而不是与局部优化器同预算比“最低分”
- 代理模型优化：这是降本工具，不是直接与权重方案同层比较的寻优器

### 7.3 维度三：预算

预算维度仍然必须保留，因为许多权重方案的“好坏”本质上是预算敏感的。

当前保留三档是合理的：

- `quick`
- `standard`
- `deep`

但预算解释需要进一步细化为：

- `quick`：用于大范围筛查，观察方案在低成本下是否已有稳定优势
- `standard`：用于比较权重排名是否开始固化
- `deep`：用于检验方案是否只是“早熟型”还是在充分搜索后仍保持优势

真正要看的不只是某一档最低分，而是四个稳定性指标：

- 平均排名
- 排名方差
- 最差格点表现
- 崩溃率或失败率

否则深预算下偶发一次低分，依然可能是“投机型公式”，而不是稳定可解释的权重设计。

### 7.4 维度四：率定顺序

这一维度需要明显收缩。与其同时保留 `joint`、`agmip_two_step`、`lai_first`、`yield_first` 四种顺序，不如聚焦于真正有文献依据、也最有解释力的两种：

- `joint`
- `agmip_two_step`

其中：

- `joint` 表示全部参数联合率定，是最直接的对照基线
- `agmip_two_step` 应代表更接近 DSSAT-PEST / AgMIP Phase 4 的标准流程：
  - 第一步：按过程分解，先率定物候参数，再率定生长/生物量参数，最后率定产量参数
  - 第二步：以第一步结果为初值，进行全参数的 WLS 联合微调，且权重应与误差方差倒数成比例

这意味着：

- `lai_first` 与 `yield_first` 可以继续保留在代码里作为探索钩子，但不应再作为第三轮正式矩阵的默认顺序
- 第三轮正式比较时，率定顺序主轴只保留“联合率定 vs 标准两步法”这两个真正有研究意义的方案

还必须明确一个当前边界：现有小麦沙箱里主观测仍以产量与 LAI 为主，尚未把 `ADAP`、`MDAP`、`CWAM` 等物候/生物量观测完整接入 `eval.py`。因此，当前 `agmip_two_step` 仍属于“代理实现”，不是完全体。真正进入第三轮正式搜索之前，最好先补齐物候与生物量观测链路，否则只能说我们在模拟 AgMIP 结构，而不能说已经严格实现了 AgMIP Phase 4。

### 7.5 诊断与验证：它不是第五维，而是硬约束

当前四维矩阵还缺少一块真正决定研究质量的内容：诊断与验证协议。

这部分不建议作为第五个可排列组合维度，而应作为所有格点都必须输出的统一报告层。至少包括：

- 残差分析：按指标、按处理、按阶段检查残差分布
- 偏差分解：报告整体 Bias、相对 Bias，以及不同处理间的系统偏移
- 独立验证误差：校准集与验证集必须严格分离

如果当前数据量尚不足以做标准的“年份外 / 站点外”验证，也应至少设计一个代理验证方案，例如：

- 按处理留一验证
- 按年份留一验证
- 或把现有处理拆为率定集与保留验证集

没有这层协议，我们拿到的仍只是“校准集内最低分排名”，还不是可发表、可复现实验意义上的稳定性地图。

## 8. 研究问题从“找最低分”转向“画稳定性地图 + 诊断面板”

四维矩阵的核心产出不应再是单个最低分，而应同时输出两类结果：

1. **稳定性地图**
   - 哪些权重方案在多优化器下保持前列
   - 哪些权重方案只对单一优化器敏感
   - 哪些权重方案在预算放大后仍保持名次
   - 哪些率定顺序会系统性改变权重方案排名

2. **诊断面板**
   - 哪些方案存在明显系统偏差
   - 哪些方案只是在个别处理上“碰巧对了”
   - 哪些方案虽然分数不最低，但残差结构更健康、验证误差更小

最终我们要保留的，不应只是“偶然最低分公式”，而应是：

- 排名稳定
- 残差结构健康
- 机理可解释
- 对预算和优化器不敏感
- 在独立验证上不过度塌陷
- 能支撑后续论文写作和复现实验的权重设计方案

## 9. 建议的执行顺序

建议按以下顺序推进第三轮前的框架收敛：

1. 固定并细化候选权重集合，至少纳入 `DSSAT-PEST` 半经验权重
2. 将默认率定顺序收缩为 `joint` 与 `agmip_two_step`
3. 在 `quick` 预算下先扫过核心优化器集合
4. 基于平均排名、排名方差、最差格点与失败率，筛掉明显不稳方案
5. 对保留方案提升到 `standard` 与 `deep`
6. 为每个候选方案输出残差分析、偏差分解与验证误差
7. 仅在上述稳定性与诊断信息都具备后，再启动第三轮 AI 自我创新搜索
