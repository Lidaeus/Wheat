# 异机研究资产复验与进一步探索方案

## 1. 文档目的

本文用于指导在另一台计算机上，基于当前**重构后的项目代码**与现有研究文档，按统一顺序开展“历史 AutoResearch 资产”的复验、筛选与进一步探索。

本文特别考虑以下现实情况：

- 早期 AutoResearch 记录中的大量结果来自**重构前代码**
- 其中一部分思想已经在重构后项目中实现
- 另一部分已经纳入当前 Phase 1 正式研究主线
- 还有一部分仍然有探索价值，但不能再直接按旧口径照搬

因此，异机研究的核心目标不是“逐字复刻历史结果”，而是：

1. 用**当前重构后代码**重新验证历史研究资产中真正有价值的部分
2. 把这些资产分流到：
   - Phase 1 主矩阵正式研究
   - Phase 1 增强层/稳健性研究
   - Phase 3 / 多目标探索研究
   - sandbox 原生 loss 自创新研究
3. 形成一套**可顺序执行、可中途止损、可持续扩展**的异机实验路线

## 2. 适用前提

本文默认另一台机器满足以下条件：

- Windows 环境
- DSSAT 已正确安装
- 本仓库代码为当前重构后版本
- `mvp_pest_mgda/.venv` 或等价 Python 环境可用
- 五作物项目配置已与当前仓库保持一致

若上述条件不满足，应先完成环境验证与最小链路 smoke，再启动本文方案。

## 3. 核心原则

### 3.1 不直接复用旧结果，只复用旧资产

历史文档中的“结论”应拆成三类：

- **已被当前项目吸收实现的资产**
- **已进入当前 Phase 1 正式研究的问题定义**
- **仍值得探索但需要在新代码上重新验证的资产**

因此，异机研究应复验：

- 方法
- 候选协议
- 假设
- 边界解释
- loss family
- 混合流程

而不是直接把旧分数当成当前正式结论。

### 3.2 先跑当前正式口径，再回收历史资产

异机研究顺序必须遵循：

1. 先确认重构后项目当前正式主线可复现
2. 再做历史资产的“映射复验”
3. 最后才做增强层和探索层扩展

否则很容易再次混淆：

- 旧评分口径
- 旧边界
- 旧 baseline
- 旧实现 bug
- 当前正式研究口径

### 3.3 Phase 1 主线优先，历史创新服从主线

当前项目中，主线已经不是“盲搜权重公式”，而是：

- `W × O × S × G` 主矩阵的核心筛选
- `B0/B1/B2` 基线对照
- `standard + train-only` 的正式运行口径
- 统一输出表和后处理链路

因此，所有历史资产都必须先判断：

- 是否应进入 Phase 1 主线
- 是否只能作为增强层
- 是否只能作为 Phase 3 或 sandbox 自创新支线

## 4. 历史资产与当前项目的对齐关系

### 4.1 已在重构后项目中落地或吸收的内容

以下内容已不再是“待发明想法”，而是当前项目的一部分：

- 多作物动态 project 配置解析
- DSSAT case 隔离与独立 workspace
- 固定宽度输入文件的更稳健改写逻辑
- `B0/B1/B2` 基线体系
- `W × O × S × G` 主矩阵组织方式
- `standard` 正式预算口径
- `train-only` 当前正式实验口径
- Phase 1 的 summary / derived metrics / combo summary 输出链路
- O1 / O2 的主矩阵正式比较入口
- 算力统计字段：
  - `eval_call_count`
  - `run_model_invocations`
  - `dssat_treatment_calls`
  - `dssat_wall_sec`

这些内容在异机上**应优先按当前实现复现**，而不是回退到旧式脚本。

### 4.2 已进入当前 Phase 1 正式研究的问题

以下历史问题已被吸收到当前 Phase 1 主线中：

- `G3` 是否优于 `G1`
- `S2` 是否优于 `S1`
- `O1` 与 `O2` 的差异是否稳定存在

- 负优化、失败率、参数贴边、组间平衡等派生指标

这些问题在异机研究中，不应另起一套旧框架，而应直接按 [04_Phase1_实验实践指南](file:///d:/Wheat/Wheat/docs/Drafts/04_Phase1_%E5%AE%9E%E9%AA%8C%E5%AE%9E%E8%B7%B5%E6%8C%87%E5%8D%97.md) 的正式框架开展。

### 4.3 仍值得单独复验或继续探索的历史资产

以下内容仍具有研究价值，但必须在当前代码上重新验证：

- `2_Inverse_RMSE`

## 5. 异机研究总路线

建议将异机研究分为 6 个阶段：

1. **Stage A：当前正式主线复现**
2. **Stage B：Phase 1 主矩阵确认与补强**
3. **Stage C：历史资产映射复验**
4. **Stage D：机制验证实验**
5. **Stage E：Phase 3 / 多目标主线**
6. **Stage F：sandbox 原生创新支线**

执行原则是：

- 只有前一阶段通过 stop/go 门槛，才进入下一阶段
- 若某阶段已足以回答核心问题，可暂停后续扩展

## 6. Stage A：当前正式主线复现

### 6.1 目标

在异机上先确认：

- 当前重构后项目能稳定运行
- 当前正式口径可复现
- 当前输出链路完整可用

### 6.2 必跑内容

1. 五作物 `B0/B1/B2`
2. 五作物 `All + standard + train-only`
3. 后处理结果生成

### 6.3 推荐执行入口

建议优先使用当前正式入口：

```powershell
python autoresearch_sandbox\phase1_runner.py --batch All --repetitions 1 --workers 14 --budget standard --tag remote_phase1_all_trainonly --crops Wheat,Maize,Soybean,Rice,Cotton --train-only
```

### 6.4 必须检查的产物

- `phase1_run_manifest.json`
- `phase1_experiment_summary.tsv`
- `phase1_derived_metrics.tsv`
- `phase1_combo_summary.tsv`

### 6.5 Stop/Go 规则

通过标准：

- 五作物主链路可运行
- 基线结果完整
- summary 字段齐全
- `train_only = true`
- 算力统计字段已落盘

若不通过：

- 先修当前链路，不进入任何历史资产复验

## 7. Stage B：Phase 1 主矩阵确认与补强

### 7.1 目标

在异机上按当前正式设计，完成或补强 Phase 1 主矩阵证据，而不是回退到旧 AutoResearch 风格矩阵。

### 7.2 执行依据

以 [04_Phase1_实验实践指南](file:///d:/Wheat/Wheat/docs/Drafts/04_Phase1_%E5%AE%9E%E9%AA%8C%E5%AE%9E%E8%B7%B5%E6%8C%87%E5%8D%97.md) 为主执行文档。

### 7.3 推荐顺序

1. `G` 识别批次
2. `S` 识别批次
3. `O` 识别批次
4. `W × O` 识别批次
5. 五作物全矩阵确认

### 7.4 当前异机任务重点

优先确认：

- `G3` 的组间平衡和失败率优势是否稳定
- `S2` 的收益是否在五作物上普遍成立
- O1/O2 的排序是否仍具有问题依赖性
- `W × O` 是否构成真实交互

### 7.5 是否立即做重复

建议分两步：

- 先做单次正式矩阵
- 再对关键组合追加重复

建议重复优先级：

- O2 高于 O1 的作物优先
- 边界贴附较严重的组合优先
- 排序接近的组合优先

## 8. Stage C：历史资产映射复验

### 8.1 目标

把旧文档中的高价值权重/协议资产映射到当前项目，而不是让它们直接污染主矩阵定义。

### 8.2 建议分流

#### C1. 作为正式对照池复验

优先候选：

- `2_Inverse_RMSE`
- `5_Mean_Normalization_NRMSE`
- `6_Log_transformation`
- `Pure_MGDA_Baseline`

这些适合作为：

- sandbox loss 对照
- 主矩阵外的稳健对照组
- 增强层比较对象

#### C2. 作为条件性方案复验

优先候选：

- `3_CV_based_R_version`
- `8_AgMIP_Two_step_WLS`
- `7_Equal_Contribution`

这些不适合直接进入主矩阵，但适合做：

- 预算敏感性实验
- 优化器敏感性实验
- 目标面稳定性诊断

### 8.3 当前建议的映射方式

不要把这些历史方案直接塞回 `W0/W4/W6/W8` 主矩阵。

更好的做法是建立一条“历史资产复验支线”：

- 固定当前评分语义
- 固定当前边界口径
- 固定当前 train-only
- 固定当前 summary 表头
- 只替换待复验的 loss / weighting family

### 8.4 推荐输出

- `legacy_asset_experiments.tsv`
- `legacy_asset_metrics_long.tsv`
- `legacy_asset_comparison.tsv`

## 9. Stage D：机制验证实验

这一阶段用于回答“为什么会这样”，而不是只回答“谁分数更低”。

### 9.1 实验 D1：目标一致性对照

目标：

- 分离 O1/O2 差异中的“算法效应”和“目标表达效应”

设计：

- 收集 O1/O2 代表参数
- 用统一评分逻辑复评
- 比较统一 `Final_Score` 与 O2 内部 `phi` 排名是否一致

优先作物：

- Wheat
- Maize
- Cotton

### 9.2 实验 D2：边界敏感性实验

目标：

- 检查当前结论是否受边界结构强烈影响

建议边界层：

- 当前项目修订边界
- DSSAT-PEST 继承边界
- 官方合法域内适度扩展边界

优先检查：

- 排序是否翻转
- 贴边比例是否显著变化
- `B0` 与优化器是否仍处于同一可行域

### 9.3 实验 D3：指标消融与权重扰动

目标：

- 检查某些引擎优势是否由少数关键指标主导

优先消融对象：

- `HWUM`
- `LAIX`
- `CWAM`
- 物候指标组

判据：

- 若移除单一指标后排序翻转，则说明当前优势是指标主导型
- 若多数消融后排序仍稳定，则更接近问题结构差异

### 9.4 实验 D4：阶段结构消融

目标：

- 判断当前观察到的结论是否依赖 `S2`

设计：

- 固定其他口径
- 对比 `S1` 与 `S2`

## 10. Stage E：Phase 3 / 多目标主线

### 10.1 启动条件

只有在以下条件满足后才建议正式进入：

- Phase 1 主矩阵结论已初步稳定
- 历史资产的主矩阵外对照已完成一轮筛选
- 当前单目标主线已足以回答 Phase 1 问题

### 10.2 推荐主线

当前最值得继续投入的是：

- `MGDA -> O1`

原因：

- 它在历史 Maize 线上已有正证据
- 它更容易形成“探索 + 精修”的可解释研究故事
- 它能自然衔接 Pareto 代表解分析

### 10.3 推荐研究对象

1. `O5 direct`
2. `O1 direct`
3. `O5 -> O1`
4. 轻量 `O4` 对照

### 10.4 推荐输出

- `pareto_archive.tsv`
- `representative_solutions.tsv`
- `hybrid_refinement_summary.tsv`
- `phase3_cross_crop_summary.tsv`

## 11. Stage F：sandbox 原生创新支线

### 11.1 定位

这一阶段不应再承担主矩阵结论任务，而应作为：

- 增强层
- sandbox 原生研究线
- loss 发明与归因研究

### 11.2 允许探索的内容

仅建议围绕以下 family 做 bounded innovation：

- `mean_relative_error + imbalance_penalty`
- `nrmse_like + treatment_variance_penalty`
- `log_error + relative_yield_guard`
- `smape_like + max_component_guard`
- `mean + max` 聚合器
- 轻量 cross penalty

### 11.3 不建议做的事

- 不要同步改优化器、边界、分组、顺序、评分语义
- 不要把外部策略收益记成 sandbox 创新收益
- 不要抢占 Phase 1 主线叙事

## 12. 异机执行顺序总表

建议严格按以下顺序推进：

1. **A1**：环境与链路 smoke
2. **A2**：五作物 `All + standard + train-only` 正式主线复现
3. **B1**：Phase 1 识别批次
4. **B2**：Phase 1 全矩阵确认
5. **B3**：关键组合重复复验
6. **C1**：历史稳健权重/损失方案映射复验
7. **D1**：目标一致性对照
8. **D2**：边界敏感性
9. **D3**：指标消融
10. **E1**：`MGDA -> O1` 五作物复验
11. **E2**：Pareto 代表解分析
12. **F1**：sandbox 原生 bounded innovation

## 14. Stop/Go 决策规则

### 14.1 进入历史资产复验前

必须满足：

- 当前正式主线可复现
- 输出表头稳定
- baseline 口径清楚
- train-only 已显式写入

### 14.2 进入 Phase 3 前

必须满足：

- Phase 1 的主矩阵问题已得到初步回答
- 不再需要通过新增主矩阵格点来解决主文问题

### 14.3 进入 sandbox 创新前

必须满足：

- 已能区分正式主结论与增强层结论
- 当前 loss 创新不会反过来污染主矩阵定义

## 15. 当前最推荐的异机优先级

### 第一优先级

- 复现当前 `All + standard + train-only`
- 完成 Phase 1 识别批次与全矩阵确认

### 第二优先级

- 做 O1/O2 目标一致性与边界敏感性
- 回收 `Log / NRMSE / MGDA` 等历史高价值对照资产

### 第三优先级

- 启动 `MGDA -> O1` 五作物复验
- 做 Pareto 代表解分析

### 第四优先级

- O2 阈值诊断收尾
- sandbox 原生 loss 的 bounded innovation

## 16. 一句话执行摘要

这套异机方案的核心不是“把重构前 AutoResearch 的旧结果再跑一遍”，而是**以当前重构后的正式 Phase 1 口径为主线，先复现并冻结主矩阵证据，再把历史 AutoResearch 中仍有价值的权重方案、边界思想、混合流程和机制假设，按增强层与探索层的方式重新接回当前项目，从而形成一条既能支撑正式研究、又能持续吸收历史研究资产的顺序化实验路线。**
