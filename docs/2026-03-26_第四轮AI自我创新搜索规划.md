# 2026-03-26 第四轮 AI 自我创新搜索规划

## 1. 轮次定位

- 第四轮不是再做一轮无边界的“策略盲搜”，而是做一轮 **面向论文归因的、受约束的 sandbox 原生策略搜索**。
- 其核心任务不是替代 `W × O × S × G` 主矩阵，而是在主矩阵之外回答一个更窄、更关键的问题：
  - **在不把 `mvp_pest_mgda` 的策略收益误记为 sandbox 创新收益的前提下，sandbox 自己演化出来的 `strategy.py`，能否形成一条可报告、可复现、可归因的改进路径？**
- 因此，第四轮应归入论文中“**搜索协议增强层 / 自主策略发明层**”，而不是主矩阵结论本身。

## 2. 为什么第四轮要这样设计

### 2.1 来自三层 baseline 方案的约束

- [2026-03-26_三层Baseline实施方案.md](file:///c:/DSSAT48/Wheat/docs/2026-03-26_三层Baseline实施方案.md) 已经固定：
  - `B0` 官方参数是 `negative_optimization` 的唯一判定锚点
  - `B1` 只是可行域诊断参考
  - `B2` 是 DSSAT-PEST 原生完整流程 benchmark
  - sandbox 默认只复用 `mvp_pest_mgda` 的执行基础设施，不默认继承其策略收益
- 这意味着第四轮如果继续把外部策略契约和 sandbox 自主 loss 发明混在一起，论文归因会失真。

### 2.2 来自路线图与实验设计的约束

- [02_Experimental_Design_Details.md](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/Research_Artifacts/02_Experimental_Design_Details.md) 已明确：
  - `W8` 是“文献参考基线 + 工程强基线”
  - `W9` 只应与真多目标优化器联用

- 所以第四轮不应扩成第五主轴，也不应把它写成“我们发现了一个新权重，主矩阵全部都要重跑”。

### 2.3 来自论文大纲的约束

- [01_Paper_Outline.md](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/Research_Artifacts/Drafts/01_Paper_Outline.md) 已明确要求：
  - 区分主矩阵结论与后续搜索协议增强结论
  - 不把局部技巧误写成普遍方法学
  - 预算敏感性与初始化敏感性属于增强研究层
- 因此第四轮最合适的论文角色是：
  - **证明 sandbox 自主策略搜索是否能在固定评价契约下产出有效候选**
  - **给出其收益边界、泛化边界与归因边界**
  - **而不是直接替代 W8、S2、G3 等主线结论**

## 3. 第四轮的核心研究问题

- RQ1：在固定 `Final_Score` 语义、不修改 `eval.py` 评分定义的前提下，sandbox 原生 `strategy.py` 能否稳定优于当前起点策略？
- RQ2：这种改进是否同时体现在 `Final_Valid_Score`、总体 `NRMSE` 与产量拟合项上，而不是只在某一个局部损失上“做分”？
- RQ3：这种改进相对于 `B0`、`W4`、`W6`、`W8` 属于什么层级：
  - 只是训练内改进
  - 还是验证集也改进
  - 还是已经具备“值得进入后续主线比较”的潜力
- RQ4：这些收益是否来自 sandbox 原生 loss 设计，而不是来自外部策略契约借用？

## 6. 本轮真正要搜索的内容

### 6.1 主搜索面：sandbox 原生 `strategy.py`

- 保持 [setup.md](file:///c:/DSSAT48/Wheat/autoresearch_sandbox/setup.md) 的硬约束不变：
  - 只允许 `numpy`
  - 只输出一个有限标量
  - 不做 I/O、随机性、环境访问、隐藏状态
  - 对同一输入保持确定性
- 候选 loss 的创新方向，建议只围绕以下五类组合件展开：
  - **尺度公平**：NRMSE、相对绝对误差、SMAPE、对数域 RMSE
  - **跨指标平衡**：均值项 + max 项、均值项 + imbalance penalty
  - **跨处理一致性**：对 treatment 间误差方差增加轻惩罚
  - **稳健误差变换**：Huber-style relative error、winsorized relative error
  - **轻耦合约束**：防止“牺牲 LAI 换 Yield”或“牺牲 Yield 换 LAI”

### 6.2 不作为本轮主搜索面的内容

- 不把 `W × O × S × G` 再整体放开重跑
- 不把 `W7/W8` 的外部策略契约改写成 sandbox 创新
- 不优先扩张到 `W9 × O4/O5` 真多目标大搜索
- 不把跨作物五作物矩阵一起并入第四轮自创新搜索

## 7. 第四轮建议拆成三段

## 7.1 Phase R4-A：归因校准段

目标：

- 先把“谁算 baseline、谁算外部策略、谁算 sandbox 原生”彻底分开

本段建议做的事：

- 固定对照对象为：
  - `B0 Official Frozen`
  - `Current_Strategy_Baseline`
  - `W4_Min_Max_Equal`
  - `W6_Log_Transformation`
  - `W8_DSSAT_PEST_Group_Max`
- 在 Wheat 上先形成一张“归因对照表”，至少包含：
  - `Final_Score`
  - `Final_Valid_Score`
  - `negative_optimization`
  - `ALL_MEAN_NRMSE`
  - `VALID_HWAM_NRMSE`
  - `VALID_HWAM_BIAS`

本段的通过条件：

- 能清楚回答“当前 sandbox 最佳起点”是谁
- 能清楚回答“这个起点是 sandbox 原生、文档权重、还是外部工程 baseline”

## 7.2 Phase R4-B：受控原生创新段

目标：

- 在固定评价契约下，真正搜索 sandbox 原生策略

建议执行方式：

- 只在 `AR_WEIGHTING = w_custom_strategy` 下运行创新循环
- 先做 **小束宽、低轮次、强约束** 的 bounded innovation
- 候选 family 优先级建议如下：
  1. `mean_relative_error + imbalance_penalty`
  2. `nrmse_like + treatment_variance_penalty`
  3. `log_error + relative_yield_guard`
  4. `smape_like + max_component_guard`
- 每一代保留信息至少包括：
  - 候选公式名
  - 哈希
  - `Final_Score`
  - `Final_Valid_Score`
  - `ALL_MEAN_NRMSE`
  - `VALID_HWAM_NRMSE`
  - 相对 `B0` 是否负优化

本段的核心要求：

- 不追求“数学花样最多”
- 只保留：
  - 验证集不退化
  - 总体 NRMSE 不恶化
  - 产量拟合不显著失真
  - 行为可解释

## 7.3 Phase R4-C：增强层可报告性筛选段

目标：

- 判断第四轮发现是否值得写入论文增强层

建议筛选规则：

- 若某候选只优于当前 `strategy.py`，但仍明显劣于 `W8`，则记为“sandbox 内部改进”，不升级为方法学亮点
- 若某候选优于当前 `strategy.py`，并且在验证集指标上逼近或超过 `W4/W6`，则记为“值得保留的原生候选”
- 若某候选在验证集、总体 NRMSE、产量拟合上同时优于当前起点，并且不触发 `negative_optimization`，则记为“增强层正式结果”
- 只有达到上一条时，才建议进入后续预算敏感性或初始化敏感性测试

### 14.6 bounded innovation 的结果

- 第四轮 bounded innovation 已执行完成。
- 最终 winner 仍然是 `Current_Strategy_Baseline`，没有新的候选超过它。
- 这说明在当前受控搜索空间下：
  - sandbox 已有 `strategy.py` 至少是一个**局部强起点**
  - 当前这批候选变体并未提供额外可见增益

  - 它表明第四轮不是“随便一搜就能更好”
  - 当前起点不是弱基线，而是已经经过前几轮压缩后的强 baseline

### 14.7 本轮出现的几个关键现象

- **现象 1：多种候选出现完全相同的最终分数 `0.267570`**
  - 不只是 `Current_Strategy_Baseline`
  - `W4`、`W6` 以及多种自动生成候选都收敛到了同一分数
- 这通常意味着至少存在以下几种可能：
  - 当前 quick budget 下，优化器把不同 loss 都带到了相同或极接近的参数盆地
  - 当前处理数和目标维度下，若干 loss family 对最终参数排序没有足够区分度
  - 当前 innovation family 的变化幅度，尚不足以改变优化轨迹的主导方向

- **现象 2：`W8` 在本轮固定协议下触发了负优化**
  - 这并不意味着 `W8` 作为文献参考方案彻底无效
  - 更准确的解释是：
    - 在本轮 Wheat、当前预算、当前协议、当前实现条件下，`W8` 这条路径没有优于 `B0`
  - 因而它更适合作为：
    - **工程强基线**
    - **受约束比较对象**
    - 而不是第四轮 sandbox 创新的收益来源

- **现象 3：当前并没有真正独立的 validation split**
  - 日志中 `Valid_TRTS: []`
  - 所以 `Final_Valid_Score` 与 `Final_Train_Score` 在本轮实际上是同一个量

### 15.4 当前 DSSAT 是否已经并行

- **此前并没有真正适配安全并行。**
- 原因不是 CPU 不够，而是旧运行方式存在共享状态：
  - `eval.py` 固定把 `params.dat`、`pest_out.dat`、`ksas_mvp*` 写在同一个 sandbox 目录
  - DSSAT case 目录默认指向共享工作目录
  - `run_model.py` 会在运行前对同名 DSSAT 进程执行全局 `taskkill`
- 在这种实现下，即使外层同时起多个任务，也会互相覆盖文件，甚至互相终止 DSSAT 进程，因此不能算真正可用的多线程并行。

### 15.5 本轮已完成的并行适配

- 本轮已对运行框架做了最小但关键的并行适配：
  - `eval.py` 改为按实际工作目录解析 sandbox 路径，而不是写死单一路径
  - `eval.py` 在直接运行 DSSAT 和调用 `pestpp-ies` 时，都会显式绑定本地 `dssat_case`
  - `run_model.py` 新增 `DSSAT_SKIP_TASKKILL` 开关，允许并行 worker 避免互相杀进程
  - `auto_evolve.py` 新增：
    - 第一批主矩阵正式批次预设 `phase1_o1 / phase1_o2 / phase1_o3`
    - `matrix` 预算档的批量调用入口
    - `--max-workers` 并行执行参数
    - 每个矩阵格点独立 worker 工作空间与独立 `dssat_case`
- 这意味着现在的并行不是“多个线程共享一个 DSSAT 目录”，而是：
  - **多个 worker 各自持有独立副本，各跑各的 DSSAT case**
- 这种方式更符合 Windows + DSSAT 的实际稳定性要求。
