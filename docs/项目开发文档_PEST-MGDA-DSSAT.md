## 2. 项目目标与范围

### 2.1 总体目标

- 面向 DSSAT（当前目录为 Wheat），实现“多目标率定”自动化流水线：
  - PEST/PEST++ 负责生成敏感性（Jacobian）与残差
  - MGDA 负责在多观测组之间求共同下降方向
  - 控制器负责更新参数并迭代，输出帕累托前沿或帕累托稳定解

### 2.2 MVP已覆盖范围

- 场景：KSAS8101（Wheat）
- 参数：土壤初始含水量（示例：sh2o_15、sh2o_30）
- 观测目标：2组（产量 HWAM、LAI LAIX）
- 迭代：单步 MGDA 更新

### 2.3 本项目开发范围（下一阶段）

- 多处理（treatment）与多场景批量运行（基于 DSSBatch.v48 或多目录复制）
- 多观测组扩展：产量/LAI/物候/土壤水分时间序列/氮素等
- 参数集扩展：遗传参数（CUL）、土壤水力参数（SOL）、管理参数（X 文件施肥/灌溉等）
- 迭代与收敛策略：步长自适应、回溯线搜索/信赖域、帕累托稳定判据
- 结果归档：每次迭代保存参数、观测误差、目标值与帕累托解集

## 3. 关键前置条件（进入正式开发前必须固化）

### 3.1 数据与文件

- 试验定义：明确要率定的 FileX（或多 FileX）与 treatment 编号
- 观测数据：每个观测必须能映射到 DSSAT 输出文件字段（Summary.OUT/Evaluate.OUT/PlantGro.OUT 等）
- 观测误差模型：至少给出每个观测组的标准差/权重策略（用于残差标准化）

### 3.2 运行环境

- DSSAT 可执行文件路径与运行方式固定（当前使用 DSCSM048.EXE 的 C 模式）
- PEST++ 可执行文件可用（pestpp-glm.exe 等）
- Python 依赖：pyemu、numpy、pandas（按需）

### 3.3 可重复性

- 禁止污染“主目录输入文件”：所有修改必须可回滚，或复制到 sandbox 目录运行
- 每次迭代必须生成可追溯工件：参数文件、JCO/JCB、REI、解析后的目标值

## 4. 系统架构与模块边界

### 4.1 模块划分

- Orchestrator（编排器）
  - 负责：迭代循环、工件目录、失败重试、收敛判定、保存结果
- DSSAT Adapter（模型适配器）
  - 负责：生成/修改输入文件、调用 DSSAT、清理输出、返回解析指标
- PEST++ Adapter（敏感性适配器）
  - 负责：生成 pst/tpl/ins，调用 pestpp-glm 生成 Jacobian 与 residual
- Objective & Parser（目标与解析器）
  - 负责：从 DSSAT 输出抽取观测对应的模拟值，组装为 PEST 输出或直接用于多目标
- MGDA Solver（多梯度求解器）
  - 负责：按观测组切分梯度，标准化，求最小范数组合，给出更新方向

### 4.2 运行数据流（每次迭代）

1) 写入/渲染参数（params.dat 或更一般的参数载体）
2) 运行 DSSAT，生成可解析的输出
3) 运行 PEST++（NOPTMAX=-1）生成 Jacobian/残差
4) MGDA 计算更新并写回参数
5) 保存工件并进入下一轮

## 5. 接口定义（文件接口 + 过程接口）

### 5.1 文件接口（强约束）

- 参数文件（推荐规范）
  - path: params.dat
  - format: 每行 `name value`
- 参数模板（PEST TPL）
  - path: params.tpl
  - format: `ptf ~`，占位符 `~name~`
- 观测输出（模型到 PEST）
  - path: pest_out.dat
  - format: 每行 `obs_name value`
- 观测指令（PEST INS）
  - path: pest_out.ins
  - format: `pif ~` + 对应读取规则

### 5.2 Python 过程接口（建议签名）

- `run_dssat(params: dict, scenario: str, trt: int, workdir: Path) -> dict[str, float]`
  - 输入：参数字典 + 场景 + treatment + 工作目录
  - 输出：与观测同名的模拟值字典

- `build_pest_case(workdir: Path, params: dict, obs_measured: dict, obs_groups: dict) -> Path`
  - 输出：pst 文件路径

- `run_pest_glm(workdir: Path, pst: Path) -> tuple[Path, Path]`
  - 输出：Jacobian（.jcb/.jco）与 residual（.rei）路径

- `mgda_update(workdir: Path, pst: Path, jco: Path, rei: Path, step: float) -> dict[str, float]`
  - 输出：新参数字典（并落盘）

### 5.3 错误处理与退出码

- DSSAT 运行失败：保存 stdout/stderr + WARNING.OUT，并返回非零退出
- PEST++ 失败：保存 .rec/.log 并返回非零退出
- 解析失败：输出文件与期望字段缺失时，明确报错并停止迭代

## 10. 工程实现极致方案（面向可复现、可扩展、可长期维护）

本章节以“把工程做到极致”为目标，在不改变总体技术路线（DSSAT → PEST++ 生成 J/残差 → MGDA 更新 → 迭代）的前提下，将方案固化为可配置、可追溯、可恢复、可验证的生产级流水线。内容同时对齐：

- 目标与范围：见本文档第 2 节
- 误差结构、数值风险与应对：参考 [PEST-MGDA 调参优化方案.md](file:///c:/DSSAT48/Wheat/docs/PEST-MGDA%20%E8%B0%83%E5%8F%82%E4%BC%98%E5%8C%96%E6%96%B9%E6%A1%88.md) 的第 5 节与第 7 节

### 10.1 不可妥协的工程约束（硬规则）

1) **工件隔离 + 幂等执行**

- 任何一次“模型运行/PEST++/MGDA 更新”都必须在独立工作目录内完成；禁止就地改写主目录输入文件。
- 每个步骤必须具备“可重入/可恢复”特性：同一 workdir 重跑不会产生语义不一致结果（允许覆盖日志/临时文件）。

2) **DSSAT 定宽文件写入零容错**

- `.X/.CUL/.SOL/.WTH` 等均为 Fortran 风格定宽格式；任何写入必须通过“字段宽度 + 对齐 + 精度”控制输出，禁止普通字符串替换。
- 所有写文件动作必须先做列宽校验（写前验）和 round-trip 校验（写后用解析器读回关键字段）。

3) **全链路可追溯与可复现**

- 每次迭代必须产出：参数快照、观测快照、模拟输出摘要、JCO/JCB、REI、MGDA 报告、对照评估（baseline/pest/mgda）。
- 记录运行环境：DSSAT EXE 路径、PEST++ EXE 路径、Python 版本、关键依赖版本、配置文件 hash、随机种子。

4) **失败可诊断、失败可继续**

- DSSAT/PEST++/解析失败时，必须写入统一的“失败原因码 + 关键日志指针”，并保留 WARNING.OUT/STDERR/REC。
- 允许以“惩罚值（penalty）”方式继续优化（用于全局搜索或多起点），但必须区分“数值失败/模型崩溃/解析缺失”。

### 10.2 工作目录与工件规范（让复盘变得像读账本）

建议将每次运行固化为一个“账本目录”（Run Ledger），结构如下（示意）：

- `runs/_runs/<stamp>/`
  - `project_snapshot/`：本次运行使用的配置与模板快照（只读）
  - `initial/`：初始点（或多起点列表）
  - `iter_000/`、`iter_001/`…：每轮迭代的完整工件
  - `pareto_archive/`：多起点/多轮产生的非支配解集合（CSV + 参数文件）
  - `run_manifest.csv`：总清单（每轮 phi/phi_w/组内指标/失败码/耗时）

每个 `iter_xxx/` 下至少包含：

- `params/`：`params.dat`（本轮参数）、`params_next.dat`（候选/接受后）
- `dssat/`：DSSAT 输入快照 + 关键输出（必要时可配置保留全部输出）
- `pest/`：`*.pst/*.tpl/*.ins/*.jco/*.jcb/*.rei/*.rec/*.log`
- `mgda/`：`mgda_report.txt`、组梯度范数、alpha、步长/回溯信息
- `eval/`：对照评估 CSV（baseline/pest/mgda 或 iter 内对照）
- `meta.json`：本轮元数据（时间、耗时、随机种子、失败码、配置 hash、输入输出摘要）

### 10.3 配置化的终点形态（“代码不再写死任何试验”）

目标是把“场景/参数/观测/误差模型/迭代策略”全部从代码迁移到配置，并提供严格 schema 校验。

建议配置分层（最终可合并为一个 `project.yml`，这里先给逻辑划分）：

- **Runtime**：DSSAT 根目录、可执行文件、PEST++ 路径、并行设置、超时策略
- **Scenarios**：FileX 列表、TRT 列表、跨年/跨站点集合、验证集划分
- **Parameters**：
  - name、lb/ub、初值、变换（none/log）、归属文件（CUL/SOL/X）、写入规则（定宽字段定义）
  - 先验（均值/方差）与正则化策略（作为目标/约束）
- **Observations**：
  - obs_name、group、来源（WHA/WHT/其他）、映射到 DSSAT 输出字段与解析规则
  - 单位与尺度、测量误差 σ、缺测策略、序列对齐策略（日期/发育阶段）
- **Optimization**：
  - MGDA 归一化策略（L2/按 σ 预白化/有效样本量修正）
  - 步长策略（初始步长、回溯参数、信赖域/限幅）
  - 多起点策略（LHS/IES）、停止准则（Pareto stationary/改进阈值/预算）

工程落地要求：

- 配置必须可被序列化进 `project_snapshot/`，并在 `meta.json` 中记录 hash。
- 任何一次运行都必须仅依赖“配置 + 模板 + 输入观测”，不依赖开发机的隐含状态。

### 10.4 DSSAT Adapter（输入渲染、执行、输出采集）

1) **输入渲染层：定宽写入器（核心资产）**

- 为 `.CUL/.SOL/.X` 建立“字段级写入函数”，明确每个字段：起止列、类型、格式化精度、缺失规则。
- 支持“从模板复制 → 定点修改 → 写回”的流水线：
  - 读模板时保留原始行（保证对齐与注释不丢）。
  - 修改时只改目标字段的字符切片，其他列原样保留。
- 内置“写后校验”：
  - 列宽不变（行长度一致或符合 DSSAT 容忍规则）。
  - 关键字段可解析回目标值（round-trip）。

2) **执行层：稳定的进程与目录管理**

- 始终显式设置 `cwd` 为本次运行目录；DSSAT 输入文件必须位于该目录或其预期结构中。
- 提供两种运行模式：
  - 单 TRT 运行：用于快速评估与调试。
  - 批量 TRT 运行：可通过 DSSAT 的批处理机制（例如 DSSBatch.v48）或循环调用 `DSCSM048.EXE C filex trt`。

3) **输出采集层：解析器的“强契约”**

- 每个观测定义必须明确“从哪个输出文件、哪个字段、哪个定位策略（表头定位/列名/正则）”。
- 解析器必须具备：
  - 字段缺失时的明确错误信息（包含文件名、期望字段、实际列集合、TRT/DATE）。
  - 可配置的容错策略：缺失即失败 / 缺失填惩罚值。

### 10.5 PEST++ Adapter（JCO/残差生成的工程化“稳定器”）

1) **运行模式标准化**

- 对 MGDA 迭代来说，优先采用“敏感性生成”模式（`NOPTMAX=-1`）：只在当前点生成 Jacobian/残差，避免把 PEST 的单目标 GML 更新混进来。
- 若需要“先单目标收敛再进入 MGDA”（例如两阶段率定的第一阶段），再启用 `NOPTMAX>0` 的 estimation 模式。

2) **残差与权重一致性**

- 明确残差构造：使用 PEST++ 输出 residual（`.rei*`）并与 `.pst` 的权重矩阵一致；保证 MGDA 使用的 r 与 J 来自同一轮同一点。
- 观测分组必须与物理意义一致（yield/laix/laid/swad/phenology…），这是 MGDA 的“目标定义”。

3) **并行与超时**

- 所有“等待文件出现”的逻辑必须统一封装，并支持：超时、重试、日志追加、最终失败原因码。
- PEST++ 的并行策略（本机多核/分布式）要配置化，避免写死到脚本里。

### 10.6 目标函数与误差模型（让多目标真正“物理上公平”）

来自 [PEST-MGDA 调参优化方案.md](file:///c:/DSSAT48/Wheat/docs/PEST-MGDA%20%E8%B0%83%E5%8F%82%E4%BC%98%E5%8C%96%E6%96%B9%E6%A1%88.md) 的关键结论是：若不处理量纲/样本量/自相关，MGDA 也会退化。

1) **预白化与归一化（默认策略）**

- 组内残差优先做 “按测量误差 σ 的预白化”：`r' = r / σ`。
- MGDA 梯度默认做 L2 归一化（关注方向冲突，而非模长差异）。

2) **有效样本量修正（时间序列必须做）**

- 对水分等高频序列，考虑自相关导致的“有效样本量远小于点数”。
- 工程实现上可采用两条路径（都需配置化）：
  - 代表性抽样：关键日期/关键层抽子集。
  - 权重折减：按经验自相关长度对组内权重做折减，使组贡献不过度膨胀。

3) **非平滑与物候跳变（两阶段 + 对齐误差）**

- 默认启用“两阶段率定”：先用单目标（或单独观测组）稳定物候，再固定物候进入 MGDA。
- 对时序指标允许“阶段对齐误差”：按发育阶段对齐后再计算误差，减少 1 天跳变造成的梯度灾难。

4) **鲁棒损失与异常点 (Huber Loss)**

- **设计思路**：为抑制 DSSAT 黑盒模拟偶发的数值震荡或异常观测值，引入 Huber Loss。在 Z-Score 归一化后的残差 $e_{norm}$ 超过阈值 $\delta$ 时，损失函数从二次方转为线性增长，从而截断极端梯度。
- **配置用法**：
  - 在 `project.json` 的 `optimization.mgda` 中设置：
    - `loss_type`: `"huber"` (默认为 `"mse"`)
    - `huber_delta`: `1.0` (默认值，即 1 个标准差之外开始截断)
- **工程实现**：在 `mgda_update.py` 的梯度装配与 `_calc_phi` 回溯判定中同步生效。

### 10.7 MGDA Solver（数值稳定、可解释、可控）

1) **梯度构造**

- 按观测组 g 构造：$\nabla L_g = J_g^T (W_g^T W_g r_g)$，与 PEST++ 的权重一致。
- 提供梯度统计输出：每组 `grad_norm`、夹角统计、alpha 系数，写入 `mgda_report.txt`。

2) **共同下降方向求解**

- k=2 使用解析解，k>2 使用 Frank-Wolfe（或等价凸优化）求最小范数组合。
- 对数值病态（近共线/近零梯度）提供退化处理：
  - 全零梯度：判定 Pareto stationary。
  - 部分近零：可丢弃近零组或设置最小范数阈值（需记录在 report）。

3) **步长策略：自适应缓存步长 (Adaptive Step Sizing)**

- **设计思路**：MGDA 对步长极度敏感。为避免每轮迭代都从默认的大步长（如 0.2）开始因发散而进行多次无效回溯（Backtracks），引入步长记忆机制。
- **自适应逻辑**：
  - 若当前轮次以 $\le 1$ 次回溯成功，则下轮起始步长尝试放大（$step_{next} = step_{curr} \times 1.5$）。
  - 若当前轮次发生 $\ge 2$ 次回溯，则下轮保持当前成功步长，不再盲目探高。
- **工程实现**：更新成功后在工作目录生成 `step_next.txt`，由 Orchestrator (`run_mvp.ps1`) 自动传递至下一轮作为 `step.txt` 输入。

4) **正则化作为额外目标/约束（抑制异因同果）**

- 将“偏离先验的惩罚项”作为单独观测组/目标，进入 MGDA 共同下降方向，从机制上压制极端参数漂移。

### 10.8 迭代控制器（Orchestrator）：把它做成“可恢复的作业系统”

1) **状态机化执行**

每轮迭代拆成固定 stage，并把 stage 完成标记写入 `meta.json`：

- `render_inputs` → `run_dssat` → `run_pestpp` → `mgda_update` → `evaluate` → `archive`

重启时读取 `meta.json`，跳过已完成阶段，实现断点续跑。

2) **停止准则与档案管理**

- Pareto stationary（共同下降方向范数 < 阈值）
- 改进停滞（phi_w 连续 N 轮改进 < ε）
- 预算停机（迭代轮数/模型运行次数/墙钟时间）
- 多起点运行时维护 `pareto_archive/`（非支配解集），并输出超体积等指标（可选）。

3) **多起点策略（把局部性问题工程化解决）**

- LHS/IES 生成一批初值 → 每个初值独立局部 MGDA 收敛 → 汇总成 Pareto 档案。
- 运行清单中记录：初值来源、失败率、每条链的最优折中点。

### 10.9 质量保证与回归（把“不会悄悄变差”写进流程）

1) **单元测试（不依赖 DSSAT 可执行）**

- 定宽写入器：字段切片写入与 round-trip。
- 解析器：给定固定样例输出（Evaluate.OUT/PlantGro.OUT），验证字段定位与 TRT/DATE 选择逻辑。
- 配置校验：schema 与必填字段。

2) **集成测试（最小 DSSAT Case）**

- 以一个极小 case（1 个 FileX + 1 个 TRT + 少量观测）作为“金标准”，验证：
  - 全链路能跑通
  - 工件目录完整
  - phi/phi_w 计算可复现

3) **运行时自检**

- 输入自检：参数边界、必需文件存在、定宽行长度检查。
- 输出自检：关键输出文件存在且非空、字段齐全、数值有限。

### 10.10 推荐实施顺序（以最少返工达到极致）

建议按“先固化接口与工件 → 再扩目标与算法 → 最后做性能与多起点”的顺序推进：

1) **M1（配置化与工件标准）**：配置 schema + run ledger + 状态机化 orchestrator（断点续跑）。
2) **M2（目标扩展与误差模型）**：观测映射全面配置化；加入 σ 预白化、有效样本量修正、鲁棒损失选项。
3) **M3（数值稳健与两阶段）**：两阶段率定、步长限幅、物候对齐误差；完善失败码体系。
4) **M4（性能与全局性）**：SVD-Assist/降维、周期性重算 Jacobian + 近似更新、多起点 LHS/IES + Pareto 档案。

完成标准（“极致”验收口径）：

- 同一配置在同一机器可 100% 复现关键输出（phi/phi_w 与参数）。
- 任一阶段失败均可定位原因且可恢复重跑。
- 观测/参数新增不需要改代码，只需改配置与模板。
- 多起点与多场景可批量执行，产出可复盘的 Pareto 档案与对照基线。

### 10.11 现有方案是否已发挥 PEST+MGDA 的最大优势（结论与差距）

以“得到效果更好、总体最优、鲁棒性强的作物遗传参数”为评价标准，当前第 10 节方案已经把工程地基打到较高水准（隔离、可追溯、误差模型、两阶段、safe step 等），但距离“最大化 PEST+MGDA 优势”仍有关键差距。

**已具备的优势（能支撑稳定提升的工程条件）**

- 工件隔离与可追溯：保证迭代可复盘、可恢复，为多起点与多场景铺路。
- 目标分组与误差建模意识：明确了“多目标必须公平”的工程约束（σ 预白化、有效样本量、鲁棒损失）。
- 数值稳健性底线：默认 safe step、两阶段率定、步长限幅，能显著降低“JCO 不可靠导致乱跳”。

**尚未发挥到极致的关键点（会直接限制“总体最优/鲁棒”）**

1) **仍偏“单点/单步”而非“帕累托前沿与鲁棒选择”**

- 当前闭环主要体现为：在某个点生成 J/残差 → MGDA 做一次更新 → 对照评估。
- 这能证明方法可行，但不足以系统获得“总体最优且鲁棒”的遗传参数：需要多起点、多轮迭代、维护 Pareto 档案，并在验证集/多环境上做鲁棒选择。

2) **PEST 单目标更新与 MGDA 多目标更新的角色需要更清晰地“解耦”**

- 若先用 `NOPTMAX>0` 的单目标估计把参数推到某个权重组合最优点，MGDA 很可能只是做“局部微调”，无法系统探索权衡曲面。
- 为最大化 MGDA 的优势，应把 PEST++ 主要用作“在当前点生成 Jacobian/残差”的高效引擎（`NOPTMAX=-1`），而让 MGDA 成为主导的多目标迭代更新器。

3) **“鲁棒性强”的定义与验收尚未工程化**

- 仅在训练期（当前观测集合）上改善 `phi_w`，并不能保证跨年/跨处理/跨管理的泛化。
- 需要把“跨环境验证误差”纳入停止准则与解的选择准则（例如 worst-case 或 CV 均值）。

4) **遗传参数与土壤/管理参数的可辨识性与互相补偿尚未被系统约束**

- DSSAT 中遗传参数与水分/氮素过程参数存在强耦合，若不加入先验与分步策略，仍易出现“看似拟合更好但机理补偿”的异因同果。
- 工程上需要把“偏离先验”的正则项真正纳入多目标框架，并将“分步/层级率定”固化为默认流程。

结论：当前方案的工程骨架是对的，但若目标是“最大化 PEST+MGDA 的方法优势并得到鲁棒遗传参数”，需要把重点从“单次闭环验证”推进到“多起点、多轮 MGDA 主导迭代、Pareto 档案 + 多环境验证选择”。

### 10.12 面向遗传参数鲁棒最优的改进清单（建议默认启用）

1) **把优化目标从“训练拟合更好”升级为“跨环境鲁棒更好”**

- 场景层面配置化：至少包含多处理（WHA/WHT 的多 TRNO）、多年度/多地点（若有）或管理扰动（灌溉/施肥差异）。
- 工程上显式划分 `train/valid`：
  - `train` 用于计算梯度与更新。
  - `valid` 仅用于选择解与决定停止（防止在训练观测上过拟合）。

2) **让 MGDA 成为主迭代器，PEST++ 只做“J/残差服务”**

推荐默认迭代协议（单条链）：

- 初始化参数 `p0`（来自先验/默认/IES/LHS）。
- 对 `k=0..K`：
  - 在 `p_k` 处用 PEST++ 生成 `J_k` 与 `r_k`（建议 `NOPTMAX=-1`）。
  - 按观测组构造 `∇L_g(p_k)`，并做预白化与归一化。
  - MGDA 求共同下降方向 `d_k`。
  - safe step（回溯线搜索）得到 `p_{k+1}`（接受条件默认以 `phi_w(train)` 不劣为硬门槛，可加容忍度）。
  - 周期性记录 `phi(train)`、`phi(valid)`、组内 RMSE、alpha、backtracks、失败码。
- 结束条件：Pareto stationary + 验证误差停滞 + 预算。

这样做的核心收益是：MGDA 可以沿着多目标权衡曲面持续推进，而不是只在单目标最优点附近做一次更新。

3) **多起点 + Pareto 档案：解决局部性，产出可选择的折中解集**

- 默认启用多起点（LHS/IES）生成 N 个初始点；每个初始点独立跑上述 MGDA 迭代链。
- 维护 `pareto_archive/`：把每条链的非支配解汇总，输出可视化与超体积等指标（可选）。
- 最终解选择从“单点最优”改为“在 Pareto 档案里按鲁棒准则选点”。

4) **把“先验合理性”变成可优化对象，而不是事后人工筛选**

- 将遗传参数先验（例如来自 DSSAT 推荐范围/历史品种）构造成一个独立观测组/目标（正则项）。
- 在 MGDA 中与产量/物候/水分等目标同等对待，从机制上压制极端参数漂移。

5) **遗传参数的默认率定策略：两阶段升级为“层级率定”**

- Stage A（环境/土壤优先）：在固定遗传参数下，先把土壤水分相关参数拟合到合理区间（或使用独立土壤观测）。
- Stage B（遗传参数主率定）：固定土壤/管理关键参数，集中率定遗传参数（P1V/P1D/P5/G1/G2/G3/PHINT）。
- Stage C（联合微调，可选）：在强先验与限幅下做少量联合迭代，避免互相补偿。

6) **把“JCO 质量”工程化：降低梯度噪声，提升 MGDA 的有效性**

- 在 `train` 侧优先保证：有限差分步长、参数扰动尺度、输出解析稳定、物候跳变被隔离。
- 在计算预算允许时，优先提升 Jacobian 质量，而不是盲目增加 MGDA 步数。
- 允许使用近似 Jacobian 更新（如 Broyden）做降本，但必须周期性重算并在 `valid` 上验收（避免方向漂移）。

7) **鲁棒解选择（“总体最优”的工程定义）**

最终推荐默认输出两类解：

- **鲁棒点**：最小化 `phi_w(valid)` 的 worst-case（跨年/跨处理/跨管理取最大）或 CV 均值。
- **解释点**：在 Pareto 前沿上提供若干代表性点（例如强调产量/强调水分机理/折中），用于科研解释与外推实验设计。
