# 文献阅读项目工作规范（DSSAT 率定与科研写作专项）

## 1. 文档定位

本规范用于约束和优化当前文献阅读项目的执行过程，服务对象是：

- DSSAT 遗传参数率定相关文献阅读
- 顺序率定、自动率定、工具比较、协议比较相关综述积累
- 科研论文写作中的证据链构建
- 后续实验设计、方法比较与讨论部分的文献支撑

本规范的目标不是“尽可能快地写摘要”，而是建立一个 **可追踪、可验证、可迭代、低幻觉风险、对论文写作直接有用** 的文献提取系统。

## 2. 总体目标

本项目的核心产出不是单篇笔记，而是一个持续增长的、可供论文写作和研究决策复用的知识系统。系统需同时满足以下目标：

1. **研究相关性最大化**  
   每篇文献的提取必须围绕当前研究问题，而不是做泛泛而谈的读书笔记。

2. **证据可追踪**  
   任何关键判断都应尽量绑定 DOI、出版商页面、索引页面、原文引句或明确的不确定性标签。

3. **不确定性显式化**  
   若未取得全文、未获得表格、未检索到代码或数据，必须明确写出，不得默认补全。

4. **增量积累**  
   每轮只处理一篇或一个最小可验证单元，但输出应可直接追加进入统一目录体系。

5. **直接服务论文写作**  
   每份摘录都必须回答：这篇文献对引言、方法、讨论、实验设计分别有什么用。

6. **控制论优化**  
   工作流必须具备反馈、纠偏、状态识别、质量门控和异常处理机制，而不是线性、一次性的“读完即结束”流程。

## 3. 适用范围

### 3.1 纳入范围

- DSSAT 及其作物模块相关文献
- 遗传参数率定、品种系数估计、cultivar coefficient estimation
- 顺序率定、阶段式率定、联合率定、WLS、GLUE、PEST、多目标优化
- 性能指标、权重设计、观测分组、协议化率定
- 与当前研究有方法迁移关系的相邻领域文献，如 hydrology calibration、protocol design、calibration chaos

### 3.2 非目标范围

以下内容默认不作为主产出对象，除非其对当前论文有直接支撑意义：

- 与研究主线无关的纯农业背景综述
- 仅做大面积 agronomy 描述而无率定、验证、协议或模型方法信息的文章
- 无 DOI、无稳定出处、无法追踪来源且无法建立可信证据链的材料
- 纯新闻、博客、论坛帖，除非仅用于辅助定位代码或数据入口

## 4. 工作边界

### 4.1 事实边界

- 不编造原文未明确给出的数值、表格、参数顺序、实验设计细节。
- 不把摘要级信息包装成全文级证据。
- 不把二手引用当作一手结论，除非明确标注“引自检索片段/索引页面/他引转述”。

### 4.2 证据边界

- 若只有摘要、索引元数据、出版商搜索片段，则该轮输出级别应明确标记为“摘要级提取”。
- 若获得全文但未系统通读，则只能声称“局部全文提取”。
- 只有在全文、关键表格、方法段和结论段都得到核验时，才可视为“高置信全文提取”。

### 4.3 工程边界

- 每轮聚焦一篇文献，避免多篇混写导致证据污染。
- 每轮必须保存到 Markdown 文件，且应放入与主题一致的目录层级。
- 每轮可以更新目录结构，但不能为追求形式复杂度而制造无必要层级。

### 4.4 写作边界

- 总结内容以中文为主。
- 原文引句保留原语种。
- 所有“适合写论文时使用”的表述，必须与原文证据或明确的研究解读区分开。

## 5. 目录与命名规范

### 5.1 顶层目录

文献阅读项目统一存放在：

- `d:\Research_Artifacts\Literature_Notes\`

### 5.2 二级目录原则

按“研究主线”而不是按年份或作者首字母分目录。建议结构：

- `00_Project_Governance/`：项目级规范、模板、索引、状态表
- `01_DSSAT_Sequential_and_Tools/`：顺序率定、GENCALC、GLUE、PEST、工具比较
- `02_Time_Series_and_Automatic_Calibration/`：时间序列与自动率定
- `03_Protocol_Chaos_and_Survey/`：survey、calibration chaos、protocol 文献
- `04_Performance_Criterion_and_Transfer/`：性能指标与相邻领域迁移

### 5.3 文件命名原则

单篇文献文件名统一采用：

- `作者姓_年份_核心主题短语.md`

例如：

- `Anothai_2008_sequential_peanut.md`
- `Buddhaboon_2018_gencalc_vs_glue_rice.md`
- `Ma_2020_modified_pest_dssat.md`

命名要求：

- 只保留第一作者姓氏
- 年份四位
- 主题短语尽量短，但要能识别研究定位
- 用下划线分隔，不使用空格

## 6. 单篇文献输出模板

每篇文献摘录至少应包含以下模块：

1. `文献信息`
2. `本轮提取说明`
3. `这篇文章为什么与你的课题高度相关`
4. `可直接引用的原文片段`
5. `面向研究设计的结构化提取`
6. `对当前实验框架的直接启发`
7. `写论文时最可能用到的内容`
8. `代码、数据、软件与可追踪链接`
9. `是否推荐阅读原文`
10. `如果阅读原文，应重点关注什么`
11. `对下一步工作的建议`
12. `一句话结论`

### 6.1 模板的最小字段要求

每篇文献必须至少明确以下信息：

- 题目
- 作者
- 期刊
- 年份
- DOI
- 稳定链接
- 当前证据级别
- 当前研究用途
- 是否取得全文
- 是否检索到代码/数据
- 是否推荐精读

### 6.2 结构化提取中的必答问题

每篇文献都应回答以下问题：

- 它解决的核心问题是什么？
- 它的率定对象、作物、模型和数据结构是什么？
- 它的方法贡献是优化器层面的，还是 protocol 层面的？
- 它用了哪些评价指标？
- 它的结果更能支撑什么论点？
- 它的局限是什么？
- 它与当前项目中的哪一个实验轴最相关？

## 7. 证据分级规范

为避免不同来源的信息混用，所有文献提取必须显式标注证据等级。

### 7.1 证据等级定义

- `E0`：仅有题名与基本元数据
- `E1`：摘要级提取，来自出版商摘要页、索引页、搜索片段
- `E2`：局部全文提取，获得部分全文内容或关键页面
- `E3`：全文通读提取，已核验方法、结果、结论主体
- `E4`：全文深度提取，已核验关键表格、图、补充材料、代码/数据链接

### 7.2 证据等级书写要求

每篇文献必须在“本轮提取说明”中写清楚：

- 当前属于哪一级证据
- 使用了哪些来源
- 哪些结论仅是摘要级
- 哪些内容仍需全文核验

## 8. 来源优先级规范

### 8.1 优先级顺序

应按以下顺序获取和核验信息：

1. DOI / 出版商页面
2. 全文 PDF 或出版商 HTML 正文
3. 补充材料、作者附录
4. Crossref / OpenAlex / Semantic Scholar 元数据
5. 学术社交平台公开摘要片段
6. 官方软件页面、项目页面、机构页面
7. 他引文献中的转述

### 8.2 来源使用规则

- 出版商摘要可用于问题、数据、结论的初步提取。
- Crossref / OpenAlex 主要用于元数据核验，不应用来替代正文分析。
- ResearchGate、Academia 等平台若出现公开摘要片段，可作为线索，但不作为唯一证据。
- 学术搜索结果中的 snippet 可以帮助定位句子，但不应替代全文证据。

## 9. 工作流程规范

单篇文献处理应遵循以下闭环流程：

### 9.1 步骤 1：任务定位

在开始阅读前，先回答：

- 这篇文献属于哪条研究主线？
- 当前处理它是为了支持哪一个论文论点？
- 它更可能服务于引言、方法、讨论，还是实验设计？

### 9.2 步骤 2：元数据核验

核验并记录：

- 标题
- 作者
- 年份
- 期刊
- DOI
- 卷期页码
- 稳定链接

若 DOI 与题目不匹配，必须停止进入下一步，先排错。

### 9.3 步骤 3：证据源收集

至少收集：

- 1 个出版商/DOI 入口
- 1 个元数据索引入口
- 若可能，1 个全文或摘要扩展入口
- 若可能，代码或数据入口

### 9.4 步骤 4：研究用途预判

先不急于写摘要，先判断它的角色：

- 基线文献
- 方法对比文献
- 历史起点文献
- 相邻领域迁移文献
- 反例或限制性文献

### 9.5 步骤 5：内容提取

提取时必须区分四类信息：

- `事实`：原文明确陈述的内容
- `数据`：数值、变量、样本量、评价指标
- `解释`：作者的解释
- `研究用途解读`：为了当前项目而做的定向分析

### 9.6 步骤 6：写作映射

每篇文献必须映射到以下至少两个位置：

- 引言能怎么用
- 方法能怎么用
- 讨论能怎么用
- 实验设计能怎么用

### 9.7 步骤 7：代码与数据定位

必须主动检查：

- 是否有 GitHub / GitLab / OSF / Zenodo / Figshare / publisher supplementary
- 是否有软件主页
- 是否有作者机构页面或项目页面
- 若没有，必须明确写“本轮未检索到”

### 9.8 步骤 8：风险标注

必须标注：

- 是否未取得全文
- 是否存在 paywall/captcha
- 是否数值来自摘要而非正文表格
- 是否方法细节仍待核验

### 9.9 步骤 9：保存与追加

- 新文献保存为独立 Markdown 文件
- 放入对应主线目录
- 不把不同文献的摘录混写到同一文件
- 后续若补读全文，应在原文件基础上追加更新，而不是重写覆盖为不透明版本

## 10. 控制论设计

本项目不是简单的信息收集，而是一个需要闭环调节的知识生产系统。以下采用控制论框架定义其运行机制。

### 10.1 系统定义

- `被控对象`：单篇文献摘录与整个文献知识库的质量
- `控制目标`：让输出同时满足高相关性、高可信度、高可写性和高复用性
- `控制器`：工作规范、质量门、反馈规则、目录结构、模板约束
- `执行器`：检索动作、交叉验证、追加搜索、结构化改写、风险标注
- `传感器`：DOI 核验结果、来源一致性、引句数量、是否取得全文、是否找到代码/数据、诊断结果
- `扰动`：付费墙、验证码、摘要不完整、元数据冲突、主题漂移、过度解读、记忆误差

### 10.2 被控变量

需持续控制的核心质量变量包括：

- `相关性`：内容是否直接服务当前研究与写作
- `真实性`：是否避免幻觉与误引
- `完整性`：是否覆盖问题、方法、结果、局限、研究用途
- `可追踪性`：是否给出 DOI、稳定链接、来源说明
- `不确定性透明度`：是否显式说明缺失与未核验部分
- `结构一致性`：不同文献是否可横向比较

### 10.3 控制输入

可调节的控制输入包括：

- 检索深度
- 来源数量
- 是否继续追全文
- 提取粒度
- 引文数量
- 风险提示强度
- 是否加入跨文献比较

### 10.4 扰动源

主要扰动源包括：

- 出版商页面反爬与验证码
- 同一文章在不同平台的题录不一致
- 摘要与正文结论强度不一致
- 旧文献缺乏代码和数据公开
- 研究主题过多导致摘要偏离当前主线
- 阅读者容易把“合理推断”误当“原文结论”

### 10.5 反馈回路

本项目设置三个反馈回路。

#### 回路 A：单篇文献质量闭环

流程：

- 设定目标用途
- 收集来源
- 形成初稿
- 检查证据级别
- 标注缺口
- 决定补搜或结束

若发现：

- 无 DOI 核验
- 关键结论仅来自 snippet
- 代码/数据未主动搜索
- 写作用途不明确

则必须回退至前一阶段补充。

#### 回路 B：主线级一致性闭环

每处理完 3–5 篇同主线文献，检查：

- 是否已经形成清晰的主线叙事
- 是否存在重复摘录而缺少对比
- 是否有核心争议点尚无代表文献
- 是否某类证据过度集中于单一工具或单一作物

若发现主线失衡，应优先补齐缺失类型文献，而不是继续机械扩展数量。

#### 回路 C：论文写作适配闭环

周期性检查：

- 现有文献是否足以支撑引言中的关键论断
- 方法章节是否已有足够文献支撑 protocol、optimizer、metric、grouping 四条线
- 讨论章节是否已有“支持 + 限制 + 相邻领域迁移”三类证据

若不能支撑，则倒推缺失文献类型并调整阅读优先级。

### 10.6 前馈控制

在正式检索之前，先做前馈判断，减少无效阅读。

前馈变量包括：

- 文献主线标签
- 可能对应的实验轴
- 预期证据价值
- 可能的全文可得性

前馈规则：

- 若文献只与背景相关但无法支撑方法与讨论，则降低优先级。
- 若文献是某条主线的历史起点，即使较旧也应优先。
- 若文献能直接连接当前实验设计变量，应提高优先级。

### 10.7 状态机

每篇文献应处于以下状态之一：

- `S0 待处理`
- `S1 元数据已核验`
- `S2 摘要级提取完成`
- `S3 局部全文提取完成`
- `S4 全文深度提取完成`
- `S5 已纳入论文论证链`

状态转移必须有依据，不得跳级声称已“深读完成”。

### 10.8 停机条件与继续条件

单篇文献可结束当且仅当：

- 元数据已核验
- 研究用途已明确
- 证据等级已标注
- 关键引句已给出或明确说明无法给出
- 代码/数据链接已搜索
- 是否推荐精读已判断
- 风险与缺口已写明

若以上任一项缺失，不应视为合格完成。

## 11. 质量门规范

每篇文献保存前必须通过以下质量门。

### 11.1 QG1：元数据质量门

检查：

- 标题、年份、期刊、DOI 一致
- 链接可追踪
- 文件名与文献身份一致

### 11.2 QG2：证据质量门

检查：

- 是否明确证据级别
- 是否区分原文事实与研究解读
- 是否避免把摘要级内容写成全文级结论

### 11.3 QG3：研究适配质量门

检查：

- 是否明确“这篇文章为什么与你的课题相关”
- 是否指向至少一个实验轴或写作位置
- 是否不是泛泛文献摘要

### 11.4 QG4：复用质量门

检查：

- 是否有可直接引用的原文片段
- 是否有结构化提取
- 是否有下一步阅读建议

### 11.5 QG5：透明度质量门

检查：

- 是否写明全文是否取得
- 是否写明代码/数据是否检索到
- 是否写明本轮缺口

## 12. 引用与表述规范

### 12.1 原文引用规范

- 引用原文时保持原语种
- 不擅自改写引文中的数值和术语
- 引文只用于支撑明确论点，不堆砌

### 12.2 中文总结规范

- 中文总结应服务研究与写作，不追求面面俱到
- 优先解释“这对当前研究有什么用”
- 若属于推断，应使用“可用于支撑”“可能意味着”“对本研究的启发是”等表述

### 12.3 风险用语规范

当证据不足时，应优先使用以下表述：

- “本轮尚未取得全文”
- “以下判断主要基于摘要级材料”
- “该点仍需回到原文方法段核验”
- “本轮未检索到公开代码/数据链接”

不得使用：

- “作者明确证明”但实际只见摘要
- “文中详细给出”但实际未见正文
- “可复现”但未见数据和代码

## 13. 代码与数据链接提取规范

### 13.1 必搜对象

每篇文章至少应检查以下入口：

- 出版商 supplementary
- GitHub / GitLab
- Zenodo / Figshare / OSF
- 软件官方页面
- 项目主页或实验室主页

### 13.2 结果记录方式

只允许以下三种结论：

- 已找到，给出链接与用途说明
- 未找到公开链接，明确写明
- 找到相关但非本文直接配套资源，必须注明“相关资源而非本文原始资源”

### 13.3 与本项目特别相关的资源

对于 DSSAT 相关文献，应额外检查：

- DSSAT 官方工具页
- 对应 crop module 页面
- 相关参数估计工具说明页
- 相关方法经典来源 DOI

## 14. 横向比较规范

当同主线文献积累到一定数量后，应能够横向比较。为此，每篇文献都应尽量抽取以下可比较字段：

- 作物
- 模型
- 参数类型
- 数据类型
- 校准策略
- 优化工具
- 评价指标
- 是否独立验证
- 是否公开代码/数据
- 对当前研究的主要用途

## 15. 更新规范

### 15.1 允许更新的情形

- 获得全文
- 发现 DOI 或题录错误
- 新发现代码/数据链接
- 原本摘要级材料被全文核验修正

### 15.2 更新方式

- 在原文件中追加或修订，但应保留透明性
- 不得悄悄把摘要级内容替换成全文结论而不说明证据变化
- 若更新较大，建议在“本轮提取说明”中写明已从何种证据等级提升到何种证据等级

## 16. 异常处理规范

### 16.1 无法获取全文

处理方式：

- 完成摘要级提取
- 明确标注证据边界
- 写明若未来获取全文应重点核验哪些部分

### 16.2 元数据冲突

处理方式：

- 以 DOI 为锚点重新核验
- 对冲突项单独说明
- 未解决前不得进入深度解读

### 16.3 无代码无数据

处理方式：

- 不视为失败
- 但必须明确写明
- 补充最接近的官方软件或方法源链接

### 16.4 文献与主线相关性不足

处理方式：

- 降低提取粒度
- 仅保留对当前研究有用的部分
- 不要为了完整性浪费大量篇幅

## 17. 项目级绩效指标

为防止项目退化为“文件越来越多，但价值越来越低”，需跟踪以下指标：

- 每篇文献是否明确服务一个研究问题
- 每篇文献是否给出证据等级
- 每篇文献是否给出代码/数据检索结果
- 每篇文献是否给出推荐阅读等级
- 同主线文献之间是否能形成比较
- 当前文献库是否已足以支撑论文关键论断

建议以“有效支撑论文的文献比例”而不是“累计文献数”作为更重要指标。

## 18. 推荐执行节奏

- 每轮只深处理一篇文献
- 同主线处理 2–3 篇后，做一次横向对比
- 每完成一个主线簇后，回写到论文论证结构中
- 优先处理对当前实验设计最关键的文献，而不是机械按年份推进

## 19. 本项目当前推荐优先级

结合现有进展，当前优先级建议为：

1. `01_DSSAT_Sequential_and_Tools`
   - 先补齐 GENCALC、GLUE、PEST 三角比较链
2. `02_Time_Series_and_Automatic_Calibration`
   - 用于支撑时间序列观测改变识别能力的论点
3. `03_Protocol_Chaos_and_Survey`
   - 用于搭建 discussion 和 broader context

   - 用于支持“指标本身塑造率定偏好”的高阶讨论

## 20. 一句话原则

本项目的根本原则是：

**宁可明确写出“本轮只做到摘要级、但证据透明且对论文有用”，也不要写出“看似完整、实则证据不清且无法复用”的文献笔记。**
