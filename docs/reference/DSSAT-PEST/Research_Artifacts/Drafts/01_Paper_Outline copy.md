# 论文初稿大纲 (Thesis/Paper Outline)

## 1. 当前是否适合进入论文组织阶段
可以，而且现在正是合适的时间点。

原因不是“结果已经跑完”，而是**论文的方法主线已经定型**：

- 已经明确主实验矩阵为 `W × O × S × G`，并固定 `B0` 为外部基线
- 已经明确五作物边界、`G3` 分组字典、统一组号模板与缺失组裁剪规则
- 已经明确 `W8` 的定位是“文献参考基线 + 工程强基线”
- 已经明确不走全排列，而走 `Phase 0 -> Phase 4` 的分步执行路线
- 已经有可直接落地的 `Phase 0 / Phase 1` 批次表

这意味着论文现在可以先写成“**方法论文骨架 + 结果占位版**”，后续随着实验推进补结果，而不需要等所有实验结束后再从零组织。

## 2. 论文定位建议
当前最适合的写法，不是把论文写成“单一算法最优性报告”，而是写成：

**一篇关于 DSSAT 遗传参数率定中“权重策略 × 优化器 × 率定序列 × 分组协议”联合设计的多作物方法学评估论文，并进一步讨论这些组合在非凸目标面下对预算、初值与局部最优风险的稳健性。**

推荐突出三层贡献：

1. **方法框架贡献**
   - 把原本常被混写的权重、优化器、阶段式协议、分组机制拆成四维主矩阵
2. **工程实现贡献**
   - 把 `DSSAT-PEST` 现有实现、`ParameterOutput.csv` 分组元数据与 `nash.pst` 回写逻辑系统化
3. **实证比较贡献**
   - 用五作物对比回答：哪些组合跨作物稳健，哪些只在特定作物成立
4. **稳健性贡献**
   - 区分“方法本身无效”和“方法在低预算下被低估”这两类完全不同的现象
5. **搜索协议贡献**
   - 区分“优化器家族本身”与“初始化 / 多启动 / 全局-局部串联”这类增强协议的作用边界

## 3. 建议标题方向

### 3.1 主标题候选
**A Multi-Crop Evaluation Framework for Genetic Parameter Calibration in DSSAT: Weighting, Optimizer, Sequencing, and Grouping as Joint Design Axes**

### 3.2 偏工程实现标题
**From DSSAT-PEST Practice to a Unified Multi-Crop Calibration Framework: Evaluating Weighting, Grouping, and Sequential Protocols**

### 3.3 偏论文基线与方法比较标题
**Revisiting Weighting Baselines in DSSAT Genetic Calibration: A Multi-Crop Comparison of Group-Based Scaling, Sequential Calibration, and Optimizer Choice**

当前最推荐使用 **3.1**，因为它最完整地覆盖了你的主线，不会把论文误写成只比较权重或只比较优化器。

## 4. 摘要组织模板
摘要建议固定成五句结构：

1. **背景句**
   - DSSAT 遗传参数率定不仅受优化器影响，还受权重、分组与率定顺序共同制约
2. **问题句**
   - 现有研究常把这些因素混在一起，导致结果难解释、难迁移、难跨作物复用
3. **方法句**
   - 本研究在五作物 `DSSAT-PEST` 框架下构建 `W × O × S × G` 主实验矩阵，并以 `B0` 为外部基线
4. **结果句**
   - 结果部分后续填入：`W8` 是否稳定、`S2` 是否优于 `S1`、`G3` 是否优于 `G1`、最稳健优化器是谁
5. **贡献句**
   - 论文输出一套可复用的多作物率定协议，而不是单次经验性调参结论

## 5. 论文结构建议

### 5.1 引言 (Introduction)
建议引言按四段展开：

1. **作物模型率定的现实难题**
   - 多量纲观测混合
   - 终产量对目标函数的数值垄断
   - 参数代偿与 Equifinality
2. **现有文献的不足**
   - 只比较优化器
   - 只比较单一权重
   - 很少把分组协议与阶段式率定纳入统一框架
3. **本文的核心问题**
   - 是否存在一组跨作物更稳健的 `W × O × S × G` 组合
4. **本文贡献**
   - 提出四维联合框架
   - 固化五作物 `G3` 分组模板
   - 重新定位 `W8` 为文献参考基线之一
   - 形成可迁移到自动化批量实验脚本的研究协议
   - 区分主矩阵结论与后续搜索协议增强结论，避免把局部技巧误写成普遍方法学

### 5.2 材料与方法 (Materials and Methods)
这一章建议按“从边界到执行”写，而不是按工具清单堆砌：

#### 5.2.1 Study System
- DSSAT v4.8+
- 五种作物：`Wheat, Maize, Soybean, Rice, Cotton`
- `DSSAT-PEST` 作为 cultivar-level calibration workflow

#### 5.2.2 Calibration Problem Definition
- 参数空间
- 观测空间
- `B0` 外部基线
- 负优化定义

#### 5.2.3 Four-Dimensional Experimental Matrix
- `W`：权重与尺度策略
- `O`：优化器引擎
- `S`：率定序列
- `G`：观测分组协议

#### 5.2.4 Observation Grouping and Cross-Crop Template
- 五作物逐作物 `G3` 字典
- 统一组号语义总表
- 缺失组裁剪规则

#### 5.2.5 Weighting Design
- 为什么需要 `W0/W4/W6/W8`
- `W8` 为什么必须作为 baseline 之一
- `W7` 与 `W1` 为什么放到后续阶段比较

#### 5.2.6 Sequential Calibration Protocol
- `S1`
- `S2`
- `S3`
- 强调 `S3` 依赖 `S2`

#### 5.2.7 Phase-Wise Execution Strategy
- `Phase 0`：可执行性与基线
- `Phase 1`：核心筛查
- `Phase 2-4`：扩展与整合

#### 5.2.8 Evaluation Criteria
- Train Fit
- Validation Generalization
- Negative Optimization Check
- Parameter Plausibility
- Engineering Cost

#### 5.2.9 Scale-Sensitivity Analysis
- 明确 `Budget` 不作为主实验轴，而作为二级稳健性分析层
- 对少数组合做 `Quick / Standard / Deep` 三档运行规模测试
- 比较均值表现、排名变化、方差收缩与失败率变化
- 重点识别“低预算弱、高预算强”的方法类型

#### 5.2.10 Initialization Sensitivity and Hybrid Search Analysis
- 明确“初值策略 / 多启动 / 全局-局部串联”不并入主矩阵，而作为筛选后的增强研究层
- 对代表性组合评估不同初值、不同随机种子下的离散度
- 比较单次局部法、单次全局法、多启动局部法、全局后局部精修法
- 同时报告性能提升与额外计算代价，避免只报最优分数

### 5.3 结果 (Results)
结果章不要按“先作物后作物”写，建议按“先问题后证据”写：

#### 5.3.1 Phase 0 Results: Executability and Pipeline Integrity
- 五作物是否都能跑通 `B0`
- `W8 × O1 × S1 × G1` 是否形成最小闭环

#### 5.3.2 Phase 1 Results: Core Screening
- `G3` 相对 `G1` 是否稳定改善
- `S2` 相对 `S1` 是否稳定改善
- `O1` 与 `O2` 谁更稳
- `W8` 作为 baseline 是否跨作物成立

#### 5.3.3 Cross-Crop Consistency and Exceptions
- 哪些结论跨作物稳定
- 哪些是作物特异结果
- 缺失组与特例组如何影响结论

#### 5.3.4 Parameter Plausibility and Negative Optimization
- 是否出现整体劣于 `B0`
- 是否出现明显参数失真

#### 5.3.5 Scale Sensitivity of Selected Methods
- `W6`、`W8`、`W4` 等代表性方法是否随预算扩容而显著改观
- 排名是否在 `Quick -> Standard -> Deep` 之间发生反转
- 稳定性是否随着预算扩大而增强
- 哪些方法适合作为“低预算默认方案”，哪些只适合作为“高预算研究方案”

#### 5.3.6 Initialization Sensitivity and Hybrid Search Gain
- 哪些代表性组合对初值高度敏感
- 多启动是否显著降低局部最优风险
- “全局搜索 -> 局部精修”是否在性能或耗时上形成优势
- 哪些增强只在少数组合上有效，不能外推成普遍结论

### 5.4 讨论 (Discussion)
讨论建议围绕四个问题：

1. **为什么 `W8` 值得保留为 baseline**
   - 来自文献
   - 与当前工程实现一致
   - 但不是统计最优
2. **为什么不能只比优化器**
   - 优化器优劣依赖损失构造与率定协议
3. **为什么分步执行优于全排列**
   - 存在协议依赖、兼容性约束、作物差异与预算约束
4. **框架的可迁移性与边界**
   - 可迁移到其他 crop-model calibration
   - 但当前仍以 cultivar-level 为边界
5. **为什么必须区分“方法效果”与“预算暴露度”**
   - 某些方法的优劣只在足够算力下才显现
   - 因此不应把一次低预算筛查结果直接上升为方法学定论
6. **为什么不能把所有初始化技巧都写进主矩阵**
   - 混合搜索更像“增强协议”而不是新的基础方法维度
   - 若不分层，会把框架问题、优化器问题与实现技巧混为一谈

### 5.5 结论 (Conclusion)
结论只回答三件事：

1. 是否找到了比“只换优化器”更有效的研究框架
2. 哪类 `W × O × S × G` 组合最值得推荐
3. 哪些组合应该作为后续研究扩展，而不是当前主结论

## 8. 当前写作定制建议
基于你现在的研究状态，最适合的定制写法是：

- **先把 Wheat 写成方法主叙事模板**
- **再把五作物写成验证与泛化层**
- **把 `W8` 写成参考 baseline，而不是最终理论赢家**
- **把论文重点放在“联合设计框架”上，而不是单个算法夺冠**
- **把“运行规模敏感性”写成稳健性分析层，而不是再升格成第五个主实验轴**
- **把“混合搜索 / warm start / 多启动”写成筛选后增强层，而不是直接扩成第五或第六主轴**

这样写的好处是：

- 即使 Phase 1 结果还没完全跑完，论文主线也不会散
- 即使某些作物出现特例，文章仍然成立，因为核心贡献是框架与比较逻辑
- 即使后面把 `W7`、`W9` 加入，文章结构也不需要重写，只需要往后补结果层
