# 已知问题与重构建议

## 1. 先给结论

这个项目能完成任务，但从软件工程角度看，属于“强依赖环境、强依赖文本位置、强依赖副作用”的脚本型工程。

也就是说：

- 可运行
- 可复现部分实验
- 但可维护性、可移植性、可扩展性都偏弱

## 2. 主要问题清单

## 2.1 目录与副本重复

该参考项目历史上曾存在镜像子目录嵌套问题；当前仓库已经把它收口到 `docs/reference/DSSAT-PEST`。

风险：

- 容易误改错文件
- 用户可能不知道哪份才是主副本
- 输出结果和脚本版本可能错位

建议：

- 保留一套主副本
- 把样例数据、副本、归档数据分目录管理

## 2.2 工作目录依赖过强

脚本使用 `getwd()` 作为根目录：

- [DSSAT_PEST.r:L4-L6](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L4-L6)

风险：

- 如果从错误目录启动，几乎所有相对路径都会失效

建议：

- 把项目根目录作为显式参数
- 或在脚本开头校验关键文件是否存在

## 2.3 DSSAT 版本号解析方式脆弱

脚本通过 `substr(DSSAT_path,9,10)` 取版本号拼接可执行文件名：

- [DSSAT_PEST.r:L135-L135](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L135-L135)
- [DSSAT_PEST.r:L417-L417](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L417-L417)

这隐含假设：

- 路径格式必须近似 `C:/DSSAT46`
- 版本号刚好位于第 9 到 10 个字符

风险：

- 如果路径变成 `D:/Apps/DSSAT48`，这个切片就失效

建议：

- 用正则从路径末尾提取版本号
- 或直接在配置文件中显式提供可执行文件名

## 2.4 固定宽度文本处理不够稳健

脚本大量依赖 `substr` 对 `.CUL`、`.pst` 做字符级修改，例如：

- 读取 `.CUL` 参数段：[DSSAT_PEST.r:L87-L87](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L87-L87)
- 截断随机参数到前 5 个字符：[DSSAT_PEST.r:L108-L108](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L108-L108)
- 修改 `pst` 控制行：[DSSAT_PEST.r:L365-L366](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L365-L366)
- 修改 `pst` 参数初值：[DSSAT_PEST.r:L501-L503](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L501-L503)

风险：

- 列宽一旦变化就会错位
- 小数位可能被截断
- 负数、科学计数法、长字符串都可能破坏格式

建议：

- 把 `.CUL` 和 `.pst` 改写逻辑封装成专门的固定宽度格式化函数
- 对每个参数定义列起止位置与格式模板

## 2.5 直接改写 DSSAT 安装目录中的原始 `.CUL`

脚本在随机试跑和 PEST 估计过程中，会直接把候选参数写回 DSSAT 安装目录下的 `.CUL` 文件：

- [DSSAT_PEST.r:L158-L160](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L158-L160)
- [DSSAT_PEST.r:L515-L515](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L515-L515)
- [DSSAT_PEST.r:L598-L598](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L598-L598)

风险：

- 外部软件目录被污染
- 中途中断可能导致 `.CUL` 未恢复
- 多任务并发会互相覆盖

建议：

- 把目标 `.CUL` 复制到本地临时目录运行
- 永远不要直接改写 DSSAT 安装目录原件

## 2.6 错误处理几乎为空

当前脚本虽然会写 [ERROR.txt](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/ERROR.txt)，但整体上没有系统异常处理。

风险：

- DSSAT 崩溃时脚本继续向下执行
- `Evaluate.OUT` 缺失或结构变化时会报错
- `pest` 未收敛时没有明确分支处理

建议：

- 每次调用 `system()` 后检查返回状态
- 在读取关键输出文件前先检查存在性
- 对 `-99` 之外的异常值增加处理

## 2.7 数据结构过度依赖矩阵与隐式位置

例如：

- `input_CropCultivar[2]` 表示作物名
- `input_CropCultivar[3]` 表示基因型文件名
- `input_CropCultivar[5]` 表示品种名

见 [DSSAT_PEST.r:L33-L35](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L33-L35)。

风险：

- 一旦 CSV 列顺序变化，脚本就 silently 出错

建议：

- 使用 `data.frame`
- 基于列名访问，而不是靠索引位置

## 2.8 脚本结构过长，缺少函数化

[DSSAT_PEST.r](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L2-L603) 基本是一个大脚本。

风险：

- 难测试
- 难复用
- 难定位 bug

建议按职责拆成函数：

- `read_config()`
- `load_cultivar()`
- `generate_random_candidates()`
- `run_dssat_once()`
- `parse_evaluate_out()`
- `build_pest_files()`
- `run_pest_once()`
- `collect_results()`

## 3. 优先级最高的重构路线

如果只做最有价值的改进，建议按这个顺序推进：

### 第一优先级

- 去掉直接改写 DSSAT 安装目录的行为
- 修复路径与版本号推断逻辑
- 把固定宽度写入封装成函数

### 第二优先级

- 把主脚本拆成函数
- 增加错误处理和日志
- 统一根目录与重复副本

### 第三优先级

- 把结果保存成结构化表格
- 增加批量作物/批量品种能力
- 为不同 DSSAT 版本做兼容层

## 4. 如果未来要迁移到 Python

这个项目很适合迁移为 Python 编排层，原因是：

- 文件处理更稳健
- subprocess 管理更强
- pandas 更适合处理配置表和结果表
- 更容易接入多目标优化或批量实验框架

最自然的 Python 模块划分会是：

- `config.py`
- `cul_parser.py`
- `dssat_runner.py`
- `evaluate_parser.py`
- `pest_builder.py`
- `calibration.py`

## 5. 一句话结论

当前项目最值得保留的是“DSSAT + PEST 的业务流程设计”；最值得重做的是“路径处理、固定宽度改写、错误处理、脚本结构化”。
