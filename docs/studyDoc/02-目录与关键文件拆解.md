## 2. 每个目录到底扮演什么角色

## 2.1 DSSAT_Files

[DSSAT_Files](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_Files) 是“模型运行现场”。

脚本会先把 DSSAT 安装目录下对应作物的 `DSSBatch.v46` 复制到本目录，然后反复执行 DSSAT，让输出文件也落在这里。

对应代码：

- 复制批处理文件：[DSSAT_PEST.r:L55-L60](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L55-L60)
- 设置工作目录：[DSSAT_PEST.r:L63-L64](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_PEST.r#L63-L64)

这里最重要的结果文件之一是 [Evaluate.OUT](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/DSSAT_Files/Evaluate.OUT)，它同时包含模拟值与观测值，后续 fitness 和 `ins` 文件都依赖它。

## 2.2 PEST_Files

[PEST_Files](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/PEST_Files) 是“校准工作现场”。

这个目录中的重要文件可以按生命周期理解：

- 输入模板：`MZCER046.tpl`、`WHCER046.tpl` 等
- 参数定义：`MZCER046.par`、`MZCER046.pmt`
- 输出提取：`Evaluate.ins`、`Measure.ins`
- 控制文件：`nash.pst`
- 执行脚本：`CUL_random.bat`、`pest1.bat`、`pest2.bat`、`pest3.bat`、`pest4.bat`、`nash.bat`
- 结果文件：`nash.rec`、`nash.res`、`nash.par`、`nash.jco`

## 2.3 PEST_software

[PEST_software](file:///d:/Wheat/Wheat/docs/reference/DSSAT-PEST/PEST_software) 不是项目源码，而是外部工具集的随仓库分发副本。

脚本通过生成 `.bat` 文件调用这里的命令：

- `tempchek`：检查 `tpl`
- `inschek`：检查 `ins`
- `pestgen`：从参数与观测文件生成 `pst`
- `pestchek`：检查 `pst`
- `pest`：正式做参数估计

## 3. 最关键的文件职责表

| 文件 | 角色 | 如果缺失会怎样 |
|---|---|---|
| `DSSAT_PEST.r` | 总调度器 | 项目无法运行 |
| `SimulationControl.csv` | 运行控制 | 找不到 DSSAT 路径，随机筛选规则丢失 |
| `CropCultivar.csv` | 目标作物/品种选择器 | 无法确定 `.CUL` 文件和目标品种 |
| `ParameterOutput.csv` | 参数和输出的元数据字典 | 无法知道要优化哪些参数、提取哪些输出 |
| `DSSAT_Files/Evaluate.OUT` | 模拟-观测对比数据源 | 无法计算 fitness，也无法构造 `ins` |
| `PEST_Files/nash.pst` | PEST 控制中心 | PEST 无法执行 |
| `Cultivar Coefficients.txt` | 最终结果摘要 | 无法快速查看最佳品种参数 |

## 4. 项目中的重复目录现象

历史上这个参考项目曾出现过镜像子目录嵌套问题，但当前仓库内保留的是归档后的单份参考副本。

这意味着项目里实际上存在两套几乎相同的资产：

- `d:\Wheat\Wheat\docs\reference\DSSAT-PEST\...`
- 历史嵌套副本 `...\DSSAT-PEST\DSSAT-PEST\...`

这通常意味着以下几种历史情况之一：

- 曾经做过整目录打包拷贝
- 用户从压缩包解压时产生了二级嵌套
- 某次实验把完整工作副本再次复制到了仓库内部

对理解项目来说，这个现象很重要，因为它会带来两个风险：

- 误改错误副本
- 结果文件与脚本不一致

在当前会话中，建议把 `docs/reference/DSSAT-PEST` 视为唯一参考副本。

## 6. 推荐的目录理解方式

如果后续要维护这个项目，最好的理解顺序不是按后缀，而是按职责：

- 先看 `CSV`
- 再看主控脚本
- 再看 `DSSAT_Files`
- 再看 `PEST_Files`
- 最后看结果文件

这样最容易建立完整数据流，而不是陷入单个文件细节。
