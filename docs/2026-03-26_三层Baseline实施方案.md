# 2026-03-26 三层 Baseline 实施方案

## 目标

- 统一 sandbox、官方参数、DSSAT-PEST 完整方案三者的比较口径
- 避免再把“边界不同”误判成“算法退化”
- 保留 DSSAT-PEST 完整流程作为正式 benchmark

## 基本原则

- 当前项目约定：`negative_optimization` 直接相对 B0 官方品种基线判定
- B1 继续保留，但用途改为“可行域诊断参考”，不再作为 `negative_optimization` 判定源
- sandbox 的遗传参数 bounds 以 DSSAT-PEST 为单一来源，默认保持一致，不再单独发散出第二套小麦边界
- autoresearch sandbox 默认只复用 `mvp_pest_mgda` 的执行基础设施，不默认继承其优化策略
- 如确需借鉴 `mvp_pest_mgda` 的策略契约，必须显式标注，避免把外部策略收益误记为 sandbox 框架收益
- baseline 必须显式记录参数来源、边界策略、权重口径、分组口径、执行契约

## 三层定义

### B0 官方品种基线

- 定义：直接使用对应品种的官方遗传参数，不做任何修改
- 用途：作为 `negative_optimization` 的正式判定源，同时参与评分与展示
- 作用：回答“官方参数在当前评分口径下表现如何”
- 边界策略：忽略 sandbox bounds，不进行裁剪

### B1 sandbox 可行域基线

- 定义：由 B0 官方参数投影到当前 sandbox 的 `project_wheat.json` 边界内后得到
- 用途：作为 sandbox 内部诊断参考，不参与 `negative_optimization` 判定
- 作用：回答“如果只看 sandbox 可行域，当前约束带来了多大偏移”
- 边界策略：强制遵守当前项目 bounds
- 保留建议：仅作为诊断 profile 保留，不作为主要对外 baseline

### B2 DSSAT-PEST 完整流程基线

- 定义：保留 DSSAT-PEST 原始流程、原始边界、原始分组、原始赋权与原始执行方式
- 用途：作为外部 benchmark
- 作用：回答“原始 DSSAT-PEST 完整方案在其原生契约下的效果如何”
- 边界策略：遵循 DSSAT-PEST 自身控制文件和元数据，不受 sandbox bounds 限制

## 判定规则

- `negative_optimization` 只允许相对 B0 判定
- B0 用于报告“官方品种参数得分”，也是状态判定基线
- B1 用于报告“可行域诊断得分”
- B2 只用于报告“完整 DSSAT-PEST benchmark 得分”
- matrix 输出同时保留 B0、B1、B2 三项结果
- 评分表额外保留总体 NRMSE 与产量拟合项，便于横向查看

## 为什么这样分层

- B0 满足“官方参数原样保留”的业务要求
- B1 保留 sandbox 约束信息，便于解释边界效应
- B2 保证 DSSAT-PEST 完整方案不会在迁移过程中被简化丢失
- 三者职责分离后，才能区分：
  - 是算法真的退化
  - 还是 sandbox 边界更严格
  - 还是外部流程与 sandbox 不是同一实验契约
