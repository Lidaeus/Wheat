# 第一轮 AutoResearch 审查与改进记录

## 1. 运行配置审查与改进（防止策略被“埋没”）

### 1.1 发现的问题
在上一轮的基础设计中，为了保证 AI 演化循环（AutoResearch）的速度，我们在 `eval.py` 中对驱动优化器（`dual_annealing` 搭配 `Nelder-Mead`）设置了极其严格的算力限制：
- **全局搜索轮次 (maxiter)**: 原设为 3 次。
- **局部搜索评估上限 (maxfev)**: 原设为 15 次。

**隐患分析**：在如此小的运行规模下，任何一种优秀的权重策略（比如能够引导全局收敛的动态权重策略）都无法在 3 轮内充分施展其梯度指引能力。这会导致所有策略的最终得分都具有很大的随机性，相当于只是在初始点附近盲目跳跃了几次，**真正优秀的权重方案极易因为迭代次数不足而产生“表现不佳”的假象，从而被错误地埋没。**

### 1.2 改进方案
针对这一问题，我们对 `eval.py` 的算力配置进行了扩容，确保策略在 AutoResearch 的对比中能够得到公平、充分的评估：
- **全局搜索轮次 (maxiter)**: 提升至 **15** 次（平衡了探索深度与单次演化的时间成本）。
- **局部搜索评估上限 (maxfev)**: 提升至 **30** 次（给予 `Nelder-Mead` 充足的微调空间）。
- **参数寻优上下界 (Bounds) 扩容**：审查发现，DSSAT 官方 SWSW7501 实验（对应 `IB1500` Manitou 品种）的真实遗传参数部分超出了之前沿用自 R 版本 DSSAT-PEST 的严格上下界。因此我们扩展了全局优化的 Bounds，以确保最佳解不会因为硬边界被截断。

## 2. 引入基准评价标准

为了给各种自动搜索的策略提供明确的对照锚点，我们新增了以下评估模式：

### 2.1 纳入 DSSAT 官方默认参数（Baseline）
- **实现方式**：提取 `WHCER048.CUL` 中对应 `IB1500` (Manitou) 的官方默认参数 `[9.33, 3.12, 331.4, 12.87, 62.22, 2.215, 86.00]` 作为 `INITIAL_GUESS`，并在 `eval.py` 中新增 `default_dssat` 模式。
- **作用**：该模式不进行任何优化，直接运行默认参数。其最终得分（客观 NRMSE 平均值）将作为“及格线”——任何率定策略如果最终得分劣于官方默认参数，即代表该策略发生了严重的“负优化”。

## 3. 引入 PEST-GLM 衍生策略

传统 PEST 工具核心采用的是 GLM（Gauss-Levenberg-Marquardt）算法。虽然我们主推无导数全局算法（如双重退火）来对抗噪声，但从科学对比的角度，必须纳入原生 PEST 的核心逻辑，并在同一平台进行平行测试。

我们在 `eval.py` 中新增了两种基于 Scipy `least_squares(method='trf')` （严格对标 PEST GLM 行为的边界信任域算法）的模式，并通过设置 `diff_step=0.1` 解决了 Fortran 模型参数微调导致导数为 0 的停滞问题。

### 3.1 原生 PEST-GLM 方案 (`pest_glm_native`)
- **设计**：直接计算所有观测值（Yield、LAI 等）与模拟值的绝对残差，拼接成残差向量直接交给 GLM 算法求解。
- **防局部最优策略**：直接将 DSSAT 官方默认参数作为 `INITIAL_GUESS` 传入。基于官方经过农业专家校准的参数起点，可以极大程度上避免 PEST-GLM 直接掉入毫无物理意义的局部“坑”中。
- **运行规模**：`max_nfev=200`（给予 GLM 充足的雅可比矩阵计算与下降空间）。

### 3.2 PEST-GLM 搭配指标分组方案 (`pest_glm_grouped`)
- **设计**：在原生残差的基础上，引入“倒数均值归一化”（Inverse Mean Normalization）分组逻辑。将产量残差除以产量观测均值，将 LAI 残差除以 LAI 观测均值，使得两种数量级截然不同的指标（产量数千，LAI 仅个位数）在雅可比矩阵中能够具有相近的梯度权重。
- **防局部最优策略**：同样从官方默认参数起点出发。
- **运行规模**：`max_nfev=200`。

## 4. 后续执行建议

改进后的 `eval.py` 已经具备了完善的评估框架，包含：
1. **9 种 AutoResearch 动态权重策略**（算力已提升）
2. **纯 MGDA 基准**
3. **DSSAT 官方默认参数基准**
4. **原生 PEST-GLM 方案**
5. **PEST-GLM 分组方案**

这些更新不仅极大增强了实验设计的严谨性，也通过合理的参数初始值、扩充的优化边界和放宽的迭代算力，彻底排除了优秀方案被错误配置“埋没”的隐患。可以通过运行 `auto_evolve.py` 进行这几项方案的完整打分与对比。
