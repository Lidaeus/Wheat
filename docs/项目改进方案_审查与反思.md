# 项目改进方案（基于 MGDA 与反向传播关系的反思与审查）

## 1. 反思视角：从“反向传播”到“黑盒梯度”
MGDA 与反向传播的共同点是“用梯度驱动优化”，差别在于梯度来源：
- 反向传播：模型内部可微，梯度精准、稳定、成本低。
- PEST/MGDA：黑盒模型靠扰动估计雅可比，梯度噪声大、成本高、敏感于尺度与权重。

因此，本项目应优先围绕“梯度质量、尺度对齐、目标公平性、可复盘性”建立工程化保障。

## 2. 关键短板（结合现状）
1. 目标尺度与权重机制缺乏统一规范，容易导致单指标主导。
2. 评估口径在多作物、多品种场景下不稳定，结论可信度不足。
3. 运行状态机与产出工件不一致，批量复盘成本高。
4. PEST-only 与 MGDA 的策略边界不清晰，导致对比不公平。
5. 观测解析与误差模型缺少配置化约束，异常难定位。

## 3. 改进目标（对齐科学性与工程性）
- 目标公平：不同指标具有可比性与可解释性。
- 过程透明：每次运行都能被复现、可追溯。
- 对比可信：baseline / pest-glm / pest-mgda 的结果在同一口径下比较。
- 可扩展：多作物多品种场景可稳定复用。

## 4. 改进方案（可执行）
### 4.1 多种指标权重方案的设计（处理量纲与采样频率不一致）
针对不同量纲（如产量 kg/ha 与 LAI 无量纲）和采样频率差异（如产量 1 次采样 vs LAI 4 次采样）导致的梯度冲突，设计以下两套权重方案策略：

1. **基于 MGDA 的动态自适应权重方案（主推方案）**
   - **核心机制**：将不同的观测类型（LAI、干重、产量）视为独立的任务（Task），由 MGDA 底层计算基于梯度几何的帕累托最优权重 α，无需人工调参即可动态寻找梯度不冲突的方向。
   - **内部 Loss 规约**：
     - **先归一化（打破量纲歧视）**：对每个观测组统一应用 **Z-Score 归一化**。必须**使用固定实测点的 μ 和 σ 常量**，以确保目标函数不随迭代漂移。
     - **计算基础损失**：对归一化残差计算 **MSE**。对于包含异常值或观测噪声较大的实测组，可替换为 **Smooth L1 (Huber Loss)** 或 **Log-Cosh Loss** 提升抗扰动能力。
     - **驱动优化**：将各组的 Loss 送入 MGDA，使量级相近的梯度供算法计算折中方向，避免大数值目标（如产量）的主导霸凌。
   - **组内动态时间权重模型（Intra-group Balanced Weighting）**：
     - 若直接使用指数或无截距的线性递增，会导致生育早期的观测点权重过低而几乎被优化器忽略，这会使模型无法拟合出苗到拔节的基础生长曲线。
     - **优化的实施方案：带底板约束的 Logistic (S型) 滑动加权（Bounded Logistic Weighting）**
       - **生物学依据**：作物的累积生长通常呈现 S 型曲线（慢-快-慢）。中后期（如开花、灌浆期）的误差对最终产量的解释贡献率陡增。因此，误差惩罚权重也应呈现一个平滑的 S 型上升，而不是突变的阶跃分布。
       - **函数设计**：
         采用带有基础底板的 Logistic 形式：
         $$w_{t} = w_{base} + \frac{w_{max} - w_{base}}{1 + e^{-k \cdot (t - t_{mid})}}$$
       - **参数工程实现定义**：
         - $t$：采样的出苗后天数（DAP）。
         - $w_{base} \ge 1.0$：强制保底初始权重（如 `1.0`），保证早期出苗、分蘖的数据不被抛弃。
         - $w_{max}$：权重的上限天花板（如 `2.0` 或 `3.0`），防止后期过度拟合而产生震荡。
         - $t_{mid}$：S 型曲线的拐点。在工程实现上，建议直接将该值设为**总生育期（观测序列最大跨度天数）的 50% 或 60%**（即大致对应封行或开花期）。
         - $k$：斜率参数。控制曲线从中后期加速爬升的陡峭程度。
       - **优势**：
         - **实现极简**：只需在组内 MSE 计算前传入时间向量 $T$ 以及超参 `(w_base, w_max, k)`，直接通过 numpy 广播计算出权重向量。
         - **物理连续**：既保住了早期的拟合底点，又对后期的误差给予了温和但坚定的惩罚放大，不会因粗暴切断物候阶段而导致梯度跳跃（Gradient discontinuity）。

2. **基于 PEST 传统框架的静态先验权重方案（基线比对方案）**
   - **倒数方差原则**：默认基础权重依据观测误差的方差倒数设置（$w_i = 1/\sigma_i$），反映数据可靠性。
   - **观测组平衡（Observation Groups）与 PWTADJ**：
     - 在 `.pst` 文件中将不同指标分为独立的观测组（如 LAI 组、Biomass 组、Yield 组）。
     - 结合使用 `PWTADJ` 等辅助工具重新分配组权重，强制指定各组对总目标函数 Φ 的贡献比例相等（如各占 1/3）。这能在静态框架下有效对抗采样不均（如自动调大产量单点权重、调小 LAI 每个点的权重），达到近似于自动平衡的效果。
   - **手工组内时间加权**：
     - 在生成 `.pst` 文件时，代码逻辑需支持为同一观测组内的观测点分配渐进增大的权重（如早期干重设为 0.5，晚期干重设为 1.5），从而在静态组内也实现对后期累积趋势的侧重。

### 4.2 评价指标的设计方案（内外口径分离）
要求区分“模型训练的优化 Loss”与“最终模型验证的评价指标”，保障优化顺畅并能提供直观且科学的模型评估。

1. **内部优化口径**：
   - 严格遵循“以组为单位 -> Z-Score 去量纲 -> 构造 MSE/Huber -> 输入优化器（MGDA动态加权或PEST组占比权重）”的标准化链路。

2. **外部展示与最终评价口径**：
   - **核心统一度量：归一化均方根误差 (NRMSE)**
     - 作为农学参数率定的核心评价指标，通过统一除以观测均值，直接消除了不同作物参数间的量纲壁垒，将所有指标的拟合误差转为百分比形式，使模型在 LAI 上的改善与产量上的改善具有直观可比性。
   - **动态序列特征评估（针对 LAI、干重等多频次采样点）**：
     - **NSE（纳什效率系数）**：核心用于评估模型对作物动态生长“变化趋势”的捕捉能力（<0 表示不如使用均值预测）。
     - **R²（决定系数）**：配合使用，衡量模拟序列与观测序列的线性相关性。
   - **截面数据特征评估（针对产量等单次终点采样）**：
     - **RE（相对误差）**：用百分比（$|Obs - Sim| / Obs \times 100\%$）直观反映最终产出结果的偏离程度。

3. **采样不均衡处理（Time-weighting 手动兜底）**：
   - 若在非 MGDA 或非 PWTADJ 的传统损失加权框架下处理 4:4:1 采样比例的数据，需采用时间加权处理：给予产量（单点）较大的经验初始权重（如乘以 4），在统计重要性上强制与动态序列组对等。

## 7. 实施记录（2026-03-01）

### 7.1 关键 Bug 修复：`pest_out.ins` 指令文件错误读取

**现象**：MGDA 梯度中，`obs_laix` 和 `obs_laid` 的 `grad_norm_raw` 高达 10⁶，比 `obs_yield` 高 6 个数量级，导致 MGDA 的 Pareto 权重计算完全失效（LAI 梯度压倒一切）。

**根本原因**：`build_pest_setup.py` 中的 `_write_pest_out_ins()` 函数，使用 PEST 的 `l1 w !obs_name!` 格式（盲目逐行推进）生成观测指令文件。然而 `pest_out.dat` 中每条 `key value` 记录之间存在空行（Windows 换行），`l1` 跳过恰好一行，因此实际读到的是错误行——LAI 被误读为产量级别的数值（~3000 vs 实际~3.0）。

**修复方案**：将指令格式改为键名标记搜索：
```
# 修复前（盲目逐行）
l1 w !laix_t01!

# 修复后（关键字定位）
~laix_t01~ !laix_t01!
```
PEST 的 `~key~` 语法会在输出文件中搜索字符串 `key`，然后读取其后的数值，不受空行影响。

**验证结果（修复前 vs 修复后）**：

| 指标组 | 修复前 | 修复后 |
|---|---|---|
| `obs_yield` | 4.72e-01 | 7.60e-01 |
| `obs_laid` | **2.50e+06** | 7.57e-02 |
| `obs_laix` | **8.27e+06** | 1.95e+00 |

修复后三组梯度均在同一量级，MGDA 的 Pareto 权重恢复为 α_yield≈0.50, α_laix≈0.50。

### 7.2 Scheme B 参数变更（Z-Score 归一化）

| 变更项 | 修改前 | 修改后 |
|---|---|---|
| 组内缩放分母 | 动态 RMSE（随迭代变化）| 固定 `σ_obs`（观测标准差常量） |
| Jacobian 同步缩放 | 仅缩放残差 `r` | 同步缩放 `r` 和 `Jg`（保持链式法则） |

### 阶段实施验证 - LHS, trust_rel, _calc_phi (2026-03-02)

我们今天完成了三大核心改进：
1. **多目标梯度计算与回溯损失（Z-Score Normalization）对齐：**
   重写了 \_calc_phi\ 以支持相同的 \(e * w / sigma_obs)^2 / size\ 归一化策略。避免在回溯截断和步长步调中被 Yield 产量主导。
2. **信赖域扩展：** 将 \	rust_rel\ 阈值调高至 \ .3\。
3. **起始点的随机化处理 (LHS)：**
   直接引入了 \scipy.stats.qmc.LatinHypercube\ 初始化，保证 MGDA 和 PEST 的测试不会再因为过于依赖官方 Baseline 而卡在局部最优解上。
4. **BUG修复（意外收获）：**
   在测试中还发现 PEST 以及 Python 运行期间经常因为随机出来的劣质参数无法走完 DSSAT 模拟（作物死亡退出），导致 \PlantGro.OUT\ 缺少数日期的输出，以至于中断系统。
   我们增设了全局环境变量 \DSSAT_ALLOW_MISSING_WHT_DATES=1\ 以及在 Python 解析里的缺省日期补 0 机制，使得 PEST 和 MGDA 都有了跨越烂参数雷区的能力而不至于直接引发崩溃。

**运行初步结果：**
经过随机初始化后测出来的第一轮数据（iter_000）：
PEST / Baseline 起始位置处于较劣解 -> Yield RMSE: 834.06, LAI RMSE: 0.744
在此位置上，MGDA 仅用了 4 次成功的回溯寻找方向，在步长 step=0.0125 下，无差别且同时地将各项目标下降：
MGDA 更新后 -> Yield RMSE: 809.50, LAI RMSE: 0.722。

可见现在改版的版本确实解决了以前原本由于单一 Yield 带偏且回溯步子迈不开、或者拒绝正向贡献更新步等种种病症！

### 7.4 阶段实施分析与高级实验计划 (2026-03-04)

**初步运行数据复盘（Iter 000）：**
- **初始位置 (Random LHS Baseline)**: 
  - **PEST-GLM**: Yield RMSE ~834.06, LAI RMSE ~0.744
  - **PEST+MGDA**: Yield RMSE ~809.50, LAI RMSE ~0.722
- **MGDA 决策步长 (`mgda_step`)**: 0.0125
- **回溯次数 (`mgda_backtracks`)**: 4
- **无量纲多目标损失 ($\Phi$)**: 从 34.89 下降到 33.53

**分析与提升空间梳理**：
1. **成功跨越帕累托停滞（突破霸凌效应）**：PEST-GLM 把产量（Yield）的 RMSE 做到了 834.06，而 MGDA 这个额外更新层在它的基础上进一步把产量 RMSE 压低到了 809.50，**同时** LAI 的 RMSE 从 0.744 也下降到了 0.722。现象表明，两个原本相冲突的目标得到了**同步降低**。这一结果证实了 Z-Score 统筹（解决量级霸凌）带来的正确性。
2. **当前步长策略依然存在保守探索的代价**：记录显示 `mgda_step: 0.0125`，且 `mgda_backtracks: 4`。算法基础设定的信任起始步长是通过 `trust_rel` 截断的，如果直接用很大的常数（由于没到自适应阶段）硬走，会导致连续发生 4 次回溯（每次乘 0.5，如 0.2 -> 0.1 -> 0.05 -> 0.025 -> 0.0125）。这说明 **MGDA 的梯度下降方向极为敏感**，稍微走大一步模型就发散报错，或者其中某个目标变得更差。它靠强行退让缩成 0.0125 才走通。因为回溯4次相当于调用了 DSSAT 评估了 4 遍并拒绝，计算成本高昂。

**后续改进方案与下一步重点（提升空间预备）：**
1. **引入自适应缓存步长策略 (Heuristic/Adaptive Step Sizing)**：
   既然发现 `0.01` 到 `0.02` 之间是一个比较安全的探索规模，建议在连续迭代中，**将上一次成功接收的 `mgda_step` （例如本轮的 0.0125）作为新一轮起点的参考基础**（例如乘以一个扩张因子 1.5 探索尝试，而不是总盲目从高点回落），这样可以大量避免每次刚开始探步时的前几次无意义的爆降回溯计算（即减少无效的 DSSAT 黑盒调用）。
2. **拉长评估轮次与多套抽样池（Parallel LHS Runs）**：
   目前的进步来自于一个独立的随机开端。要充分验证 PEST+MGDA 曲线究竟在大后期是否绝对压倒单纯的 PEST-GLM，我们需要将轮次 `MGDA_MAX_ITER` 放大（至 5 轮或 10 轮），并且开启脚本中并行的多套 LHS 初始化点生成测试进行汇总。这将会是接下来正式产出论文级别图表的必经途径。
